# 문서 표시와 읽기 설정

합의 상태: 아래 첫 버전 기능과 기본 사용자 흐름 합의. 2026-10-27 확장 문법 기능 채택 합의 반영. 문법의 상세 호환 범위와 미정 정책·디자인은 구현 전에 구체화한다. 기능 채택과 구현 완료는 구분한다.

## 사용자와 목표

공부하거나 작업하며 작성한 Markdown 문서를 모바일에서 읽는다. 문서의 코드·표·이미지·수식·다이어그램을 확인하고 본문 크기를 읽기 편하게 조절한다.

## 핵심 시나리오

- 파일 하나를 열어 본문을 읽고, 연결된 로컬·웹 이미지를 확인한다.
- 코드 블록을 가로로 읽거나 복사하고 이미지·Mermaid를 확대해 확인한다.
- 웹 링크는 브라우저에서, 접근 가능한 상대 경로 Markdown 문서는 MDive에서 연다.
- 이미지 접근이나 수식·Mermaid 표시가 실패해도 나머지 본문은 계속 읽는다.

## 첫 파일 선택 흐름의 복원 합의

stash의 2026-10-26 기록에서 복원한 범위다. 아래 확정 사항 외의 문법·권한·복귀 정책은 열린 결정으로 유지한다.

- 홈의 파일 선택 취소는 홈 유지, 홈에서 직접 연 문서의 상단 뒤로·시스템 뒤로는 홈 복귀다. 열기 실패는 읽기 화면에서 재시도·홈 복귀를 제공한다.
- 수식은 `$…$`·`$$…$$`, Mermaid는 `mermaid` 코드 블록을 사용한다. 수식은 S06, Mermaid는 S07의 확정 프로필을 따른다.
- 사용자가 연결한 폴더를 문서 기준 폴더로 해석해 하위 상대 경로의 로컬 이미지를 읽고 연결을 앱 재실행 후에도 유지한다. 파일 하나의 접근 권한이 주변 파일 권한을 뜻하지 않는다.
- 웹 이미지는 온라인에서 읽고 실패 시 본문 읽기를 유지하면서 재시도를 제공한다. 로컬 폴더 연결과 웹 이미지 재시도는 구분한다.

## S02 로더 경계 · 확정

2026-10-27 사용자 결정. 최종 문법 지원 프로필과 원문 표시 정책은 이 로더 계약에서 정하지 않는다.

- 시스템 파일 선택기는 MIME 보고 차이로 Markdown 파일이 숨지 않도록 파일 전체를 표시한다. 선택된 표시 파일명의 마지막 확장자를 대소문자 구분 없이 검사해 `.md`·`.markdown`·`.txt`만 허용한다. 다른 파일은 열기 실패다.
- 인코딩은 UTF-8(선두 BOM 허용), 선두 BOM이 있는 UTF-16 LE/BE를 지원한다. BOM 없는 입력은 UTF-8로 해석하며 잘못된 바이트를 대체 문자로 조용히 바꾸지 않고 실패로 안내한다. 선두 인코딩 BOM 외의 원문 공백·개행은 보존한다.
- 파일 상한은 **5 MiB(5 × 1024 × 1024바이트)**다. 제공자가 알리는 크기가 없거나 부정확해도 실제 읽은 바이트에 상한을 적용한다. 상한 초과는 열기 실패이며 일부 내용만 성공으로 처리하지 않는다.
- 선택 취소는 홈 유지다. 선택기 또는 읽기가 진행 중일 때 중복 요청을 무시한다. 읽기 중 상단 뒤로·시스템 뒤로는 읽기 작업을 취소하고 홈에 복귀하며 늦은 결과로 다시 진입하지 않는다.
- 재시도는 같은 URI를 새로 읽는다. 접근 거부·삭제·지원 밖 파일·잘못된 인코딩·크기 초과는 읽기 실패에서 이유와 재시도·홈 복귀를 제공한다. 기존 홈 바로가기의 재연결·목록 제거는 H01 범위로 유지한다.
- 파일 접근은 현재 세션의 선택 권한만 사용하며 영속 권한·최근 목록·주변 폴더 접근을 추가하지 않는다.
- 표시 파일명을 제공하지 않거나 빈 이름인 파일은 확장자를 검증할 수 없으므로 열기 실패로 안내한다. URI 경로를 파일명으로 추정하지 않는다.
- 회전 시 선택·읽기 상태를 유지한다. 프로세스 재생성 시 같은 URI 재읽기를 시도하고 권한이 사라졌으면 실패·재시도·홈 복귀로 안내한다. 재실행 이후 접근 보장을 뜻하지 않는다.
- S02 제품 성공 화면은 파일명과 ‘파일을 읽었어요. 본문 표시는 다음 단계에서 연결됩니다.’ 중간 안내를 표시한다. 실제 원문은 debug 개발 테스트 호스트에서만 표시·검증하며 제품의 최종 표시 정책으로 채택하지 않는다.

수용 기준은 실제 시스템 선택·취소와 제목·원문 읽기, 로딩·빈 파일·실패·재시도·홈 복귀다. 원문은 개발 테스트 호스트에서 확인하며 Markdown 렌더 완료의 증거로 간주하지 않는다.

## S03 기본 본문 프로필 · 확정

2026-10-28 사용자 결정. 기본 해석 기준은 **CommonMark 0.31.2**다. 전체 CommonMark/GFM 및 채택 확장 지원 완료를 뜻하지 않는다.

- S03은 ATX/Setext 제목, 문단, 강조·굵게(중첩 포함), 인라인 코드, 인용, 순서/비순서 목록, 구분선을 표시한다. 기본 문법의 escape·문자 참조·줄바꿈은 CommonMark 해석을 따른다.
- 잘못 닫힌 강조 등 미완성 기본 문법은 CommonMark의 일반 텍스트 해석을 따른다. 문서 전체를 오류로 바꾸지 않는다.
- 아직 지원하지 않는 코드 블록·이미지·링크·HTML·확장 문법은 실행·이동·리소스 요청 없이 원문을 보존해 표시한다. 링크 목적지나 이미지 원문을 조용히 버리지 않는다. 기본 파서가 별도 문법으로 인식하지 않는 확장은 텍스트로 남으며 이 단계에서 방언을 추가 해석하지 않는다. 미인식 확장 안의 기본 CommonMark는 해석될 수 있다(예: `~~**굵게**~~`는 `~~`를 남기고 굵게를 적용). 지원 밖 확장 전체의 바이트 단위 원문 보기 기능을 뜻하지 않는다.
- GFM 표·읽기 전용 task·취소선은 S04, 코드 강조·복사는 S05, 수식·Mermaid는 S06–S07, 이미지·링크와 나머지 확장은 각 후속 단계에서 연결한다. 중간 원문 표시는 해당 기능의 최종 표시 정책이 아니다.
- S02 성공 중간 안내를 실제 기본 본문으로 교체한다. 파일명과 S02의 파일 선택·인코딩·크기·취소·중복·권한·실패 복구 계약은 유지한다.

수용 기준: 정상·미완성·미지원 혼합 fixture에서 기본 구조와 원문 보존을 확인한다. 실제 파일 선택→파일명과 기본 본문→홈 복귀, S02 실패·재시도 회귀, 긴 제목·좁은 폭·큰 글자를 검증한다. 미지원 영역 때문에 주변 본문 읽기를 중단하지 않는다. 후속 문법의 정확한 방언·상호작용은 열린 결정으로 남긴다.

## S04 GFM 본문 프로필 · 확정

2026-10-28 사용자 승인(표·task) 및 조사 후 결정 위임(취소선). S03 CommonMark 0.31.2 기반을 유지하며 이번 범위의 GFM 표현만 추가한다.

- **표:** 헤더와 구분 행의 열 수가 정확히 같을 때만 인식한다. 본문에서 부족한 셀은 빈칸으로 채우고 초과 셀은 GFM에 따라 생략한다. 좌/중앙/우 정렬, escaped pipe(`\|`), 셀 내부 인라인 문법을 지원한다. 셀 병합과 여러 줄 셀은 지원하지 않는다. 유효하지 않은 표는 기본 본문으로 해석한다.
- **표 표시:** 긴 셀은 열 안에서 줄바꿈하고 표 블록만 가로 스크롤한다. 기존 DS의 기본 160dp 열 폭을 사용한다. 코드와 표 외 문서 전체의 가로 넘침을 만들지 않는다.
- **task:** 목록 항목의 첫 블록이 문단이며 그 시작의 `[ ]`·`[x]`·`[X]` 뒤에 공백이 있는 GFM 표기를 인식한다. 순서/비순서·중첩 목록에 적용한다. escape·문자 참조로 만든 대괄호는 task 표기가 아니다. 두 상태만 전달하고 탭·포커스·편집 동작을 제공하지 않는다. 완료 본문에 자동 취소선을 추가하지 않는다.
- **취소선:** `~~…~~`만 지원하고 강조·굵게와의 중첩을 허용한다. 단일·불일치·3개 이상의 물결표와 미완성 구분자는 일반 텍스트로 남긴다. 코드 내용과 아직 보존 중인 링크·이미지 원문은 변경하지 않는다. 이는 단일 물결표도 허용하는 GFM과의 명시적 예외다.
- 후속 코드·수식·이미지·링크·HTML·확장은 실행·이동·리소스 요청 없이 S03 원문 보존 정책을 유지한다. S02 로더와 실패 복구 경계도 유지한다.

취소선 결정 근거: [GitHub 사용자 안내](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#styling-text)와 [GFM](https://github.github.com/gfm/#strikethrough-extension-)은 단일·이중 표기를 허용한다. [GitLab 안내](https://docs.gitlab.com/user/markdown/#emphasis)는 이중 표기를 제시하고 [markdown-it 14.1.0 구현](https://github.com/markdown-it/markdown-it/blob/14.1.0/lib/rules_inline/strikethrough.mjs)은 두 개 미만을 거부한다. 공통 표기인 이중 물결표를 채택한다. 후속 아래첨자 구분자는 이번에 정하지 않는다.

수용 기준: 정상·중첩·미완성·지원 밖 fixture, 표의 행/열 차이·정렬·긴 셀·escaped pipe, task 두 상태와 읽기 전용 의미, 취소선 중첩과 주변 본문을 확인한다. S03 기본 문법·원문 보존 및 S02 실패 경로를 회귀 검증한다. 좁은 폭·큰 글자에서 표 내부 스크롤과 나머지 본문 줄바꿈, 실제 선택→혼합 본문→홈 흐름을 확인한다.

## S05 코드 프로필 · 확정

2026-10-28 사용자 결정. CommonMark 코드 블록의 본문에 문법 강조·복사·가로 스크롤을 연결한다. 정책 확정은 구현·검증 완료를 뜻하지 않으며 실제 현황은 [구현 계획](../implementation/open-markdown.md#현재-인계)을 따른다.

- **강조 언어:** C, C++, Dart, Java, Kotlin, Rust, C#, CoffeeScript, JavaScript, Perl, Python, Ruby, Shell, Swift, TypeScript, Go, PHP의 17개 언어를 지원한다. JSON·YAML·SQL·HTML·XML·CSS 등 지원 밖 언어는 단색으로 표시한다.
- **언어 식별:** fence info string의 첫 공백류 문자(공백·탭 등) 전 토큰을 대소문자 구분 없이 해석한다. 지원 언어와 별칭은 아래 표를 따른다. 뒤의 추가 정보는 실행하거나 별도 속성으로 해석하지 않는다. 언어 라벨은 입력된 첫 토큰을 표시하며 언어가 없으면 라벨을 생략한다.
- **대체 표시:** 언어 없음·미지원 언어·강조 실패에는 자동 언어 감지를 하지 않는다. 단색 코드와 복사를 유지하며 과도한 오류 배너를 추가하지 않는다. 강조 실패가 주변 본문 읽기를 중단하거나 원문을 바꾸지 않는다.
- **코드 원문과 복사:** fence·info string 및 인용·목록 등 Markdown 구조용 들여쓰기를 제외한 코드 본문 전체를 표시·복사한다. 코드 본문 안의 공백·탭·빈 줄·끝 개행을 보존하며 복사용 텍스트에 언어 라벨이나 강조 정보를 넣지 않는다. 긴 줄을 자동 줄바꿈하지 않고 코드 블록 안에서 가로로 읽는다.
- **복사 성공:** Android 13(API 33) 이상은 시스템 복사 안내를 사용하고 앱 성공 안내를 중복 표시하지 않는다. 이전 버전은 앱에서 짧은 `코드를 복사했어요` 안내를 제공한다.
- **복사 실패:** `복사하지 못했어요. 다시 시도해주세요`를 안내하고 본문과 기존 복사 버튼을 유지해 다시 시도할 수 있게 한다. 실패를 성공으로 안내하지 않는다.
- **후속 경계:** `mermaid` fence는 S07까지 fence를 포함한 기존 전체 원문 표시를 유지한다. 수식·이미지·링크·HTML 등 후속 범위의 정책과 원문 보존 경계는 이번에 변경하지 않는다.

Highlights 1.1.0의 기본 토큰 강조를 사용하며 각 언어 최신 문법과의 완전한 호환을 보장하지 않는다. 강조 엔진은 data 내부에서만 사용하고 파서 AST·강조 엔진 타입을 domain이나 UI에 전달하지 않는다. 앱 소유 코드 본문·강조 범위 모델을 기존 MVI·Hilt·DS에 연결한다. 별칭은 아래의 명시적 앱 매핑이며 미등록 표기를 자동 추정하지 않는다.

## S06 수식 프로필 · 확정

2026-10-28 사용자 결정. [GitHub 수식 작성 안내](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/writing-mathematical-expressions)의 입력 형식을 지향하며 렌더링은 오프라인 기본 TeX의 앱 제한 프로필을 사용한다. GitHub의 MathJax 전체 호환이나 모든 TeX 명령 지원을 뜻하지 않는다. 정책 확정은 구현·검증 완료와 구분하며 실제 결과는 [구현 계획](../implementation/open-markdown.md#현재-인계)을 따른다.

- **인라인:** `$…$` 및 달러와 백틱으로 감싼 ``$`…`$``를 같은 줄 안에서 인식한다. 내용은 공백만으로 구성될 수 없지만 시작·끝 공백이나 인접 숫자에 별도 제한을 두지 않는다. 따라서 통화 표기에 달러가 짝으로 나타나면 수식으로 인식할 수 있으며 일반 달러는 `\$`로 escape한다. 닫는 구분자 직전 연속 역슬래시가 홀수 개면 escape된 것으로 보고 짝수 개면 구분자로 인식한다. 줄바꿈을 가로질러 인식하지 않는다. 인라인 시작·끝 구분자는 연속 달러의 일부로 인식하지 않으며 HTML 태그를 가로지르는 인라인 후보도 수식으로 만들지 않는다. 코드 내용과 원문 보존 중인 링크·HTML 내부는 수식으로 해석하지 않는다. 기본 Markdown과 중첩된 수식 및 표 셀의 수식은 주변 본문 구조를 유지한다.
- **블록:** 새 줄의 첫 내용이 `$$`인 `$$…$$`를 같은 줄 또는 여러 줄로 작성할 수 있다. 시작 들여쓰기는 CommonMark 기준 4칸 미만이며 `$$$`로 시작하면 블록 수식으로 인식하지 않는다. 끝의 공백을 제외한 행 마지막의 escape되지 않은 정확히 두 개의 `$$`로 닫고 세 개 이상 연속된 달러는 닫는 구분자로 쓰지 않는다. 인용·목록 안에서는 해당 컨테이너의 내용 줄을 기준으로 처리한다. 닫힌 코드 fence의 info 첫 토큰이 소문자 `math`와 정확히 같을 때도 수식 블록으로 인식하며 뒤의 추가 info는 해석하지 않는다. 빈 내용이나 미완성 구분자·닫히지 않은 `math` fence는 원문으로 남긴다. escape와 일반 달러 표기를 보존하며 정밀한 공백·숫자 인식 휴리스틱까지 GitHub와 완전 호환이라고 주장하지 않는다.
- **지원 프로필:** 분수·근호·첨자·그리스 문자·합/적분·행렬 등 기본 TeX를 지원한다. JLatexMath Android 0.2.0을 사용하며 허용 명령·환경은 아래 목록으로 제한한다. 목록에 있더라도 인자나 구문이 잘못돼 엔진이 표시하지 못하면 해당 수식의 실패로 처리한다. 사용자 정의 매크로, 외부 리소스 로딩, HTML/URL 명령은 지원하지 않는다. 미지원 명령을 조용히 없애거나 성공으로 표시하지 않는다.
- **표시:** 정상 수식에 오류 배너나 별도 원문 보기·확대 동작을 추가하지 않는다. 긴 블록 수식은 해당 영역 안에서 가로로 읽는다. 가용 폭보다 긴 인라인 수식은 별도 행으로 옮겨 수식 영역 안에서 가로로 읽으며 문서 전체를 가로로 넘치게 하지 않는다. 본문과 함께 큰 글자·라이트/다크 표시를 확인한다.
- **실패:** 인식된 수식의 미지원 명령·렌더링 실패에는 해당 위치에 `수식을 표시하지 못했어요`와 `원문 보기`를 제공하고 주변 본문 읽기를 유지한다. 미완성 또는 빈 수식의 원문 표시는 렌더링 실패와 구분한다.
- **원문 보기:** 실패 영역의 버튼으로 읽기 전용 시트를 연다. 수식의 구분자 또는 fence를 포함한 원문을 보여주고, 별도 닫기 버튼 없이 아래로 스와이프·바깥 영역 탭·시스템 뒤로로 시트만 닫아 기존 본문 위치에 복귀한다. 원문을 편집하거나 실행하지 않는다.
- **접근성:** 정상 수식에는 `수식: TeX 원문`을 대체 설명으로 제공한다. 실패 영역의 안내·원문 보기와 시트 닫기에도 접근할 수 있어야 한다. 자연어 수학 낭독으로 변환하는 기능은 이 프로필에 포함하지 않는다.
- **후속 경계:** Mermaid 종류·버전·확대, 이미지·링크·HTML 등 후속 정책은 확정하지 않는다. 일반 코드의 원문·강조·복사와 S02 로더 경계를 유지한다.

### S06 허용 TeX 목록과 처리 한계

각 항목은 역슬래시 뒤의 명령 이름이다. 목록 밖 명령은 실패 처리한다. `{…}` 그룹, 일반 문자·숫자·연산 기호, 첨자의 `^`·`_`는 TeX 구문으로 해석하며 원문을 Markdown 강조로 다시 해석하지 않는다.

## S07 Mermaid 프로필 · 확정

2026-10-29 사용자 결정. `mermaid` fence를 일반 코드와 구분하며 다음의 제한 프로필을 사용한다. S06 수식 프로필과 후속 이미지·링크·HTML 정책을 변경하지 않는다.

- **실패·원문 보기:** 지원 밖 종류·문법·금지된 기능·렌더 실패·한계 초과에는 해당 위치에 `다이어그램을 표시하지 못했어요`와 `원문 보기`를 제공한다. 정상 다이어그램에서도 원문 보기가 가능하다. 원문은 fence를 포함한 읽기 전용 시트에 표시한다. 원문을 편집하거나 실행하지 않으며 별도 닫기 버튼을 두지 않는다. 아래로 스와이프·바깥 영역 탭·시스템 뒤로는 시트만 닫고 기존 본문 위치를 유지한다.
- **확대·탐색:** 정상 다이어그램 탭으로 확대 화면을 열고 전체가 들어오는 맞춤 배율로 시작한다. 콘텐츠 옆에 별도 확대 버튼을 두지 않고 그림 자체에 접근 가능한 확대 동작을 제공한다. 맞춤 대비 **1–8배**에서 두 손가락 확대·축소와 드래그 이동을 제공하고 `맞춤` 행동으로 초기 배율·위치를 복원한다. 확대·축소·맞춤은 아이콘으로 제공하며 배율 표시와 함께 하단의 한 컨트롤 영역에 묶고 닫기는 상단에 둔다. 확대 화면의 닫기·시스템 뒤로는 확대 화면만 닫고 기존 본문 위치로 돌아간다. 다시 진입하면 전체 맞춤으로 시작하며 이전 확대·이동 상태를 저장하지 않는다.
- **접근성:** 다이어그램의 종류와 원문을 확인할 수 있는 설명, 원문 보기·확대·맞춤·닫기의 명확한 이름을 제공한다. 다이어그램 노드 관계의 자연어 해설은 이 프로필에 포함하지 않는다. 좁은 폭·큰 글자에서도 복구·확대 행동에 접근할 수 있어야 한다.

수용 기준: 지원한 다섯 종류별 정상 입력, 미완성·지원 밖 종류/문법, 금지된 HTML·외부 요청·링크·문서 설정, 엔진 실패·50,000자/500개 연결선/10초 한계 경계를 fixture로 확인한다. 긴·큰 다이어그램과 라이트/다크·좁은 폭·큰 글자·접근성을 확인한다. 정상 및 실패의 fence 원문 시트→아래 스와이프/바깥 탭/시스템 뒤로→본문 위치 유지, 그림 탭→맞춤 초기→핀치/팬→맞춤 복원→닫기/뒤로→동일 본문 복귀→재진입 초기화를 검증한다. 실제 파일 선택→수식/일반 코드/Mermaid 혼합 본문→확대/복귀→홈을 가능한 기기에서 확인한다. S06 수식과 원문 시트·S05 코드/복사 및 S02–S04를 영향 범위에서 회귀 검증하며 실제 검증과 미검증은 구현 인계에 구분한다.

## S08+S09 이미지 프로필 · 확정

2026-10-29 사용자 결정. 로컬·웹 이미지 표시와 이미지 확대에 다음 프로필을 적용한다. 본문을 먼저 표시하고 일부 이미지의 준비·실패 때문에 문서 읽기를 중단하지 않는다. Mermaid는 S07 프로필을 유지하며 후속 링크·HTML·미디어 정책은 확정하지 않는다.

- **지원 형식:** PNG·JPEG·WebP·GIF의 첫 프레임과 스크립트·외부 리소스 없는 정적 SVG를 지원한다. 애니메이션은 재생하지 않는다. 그 외 형식 또는 지원하지 않는 SVG 기능은 해당 이미지의 지원 밖 안내와 대체 설명으로 남기고 주변 본문을 유지한다. SVGZ·애니메이션·필터·foreignObject는 지원하지 않는다. 정적 SVG도 안전한 렌더링을 위해 XML 요소 10,000개·깊이 128·내부 참조 10,000개·참조 확장 작업량 50,000개까지로 제한하며 순환 참조·외부 스타일시트/CSS URL은 거부한다. 도형 속성의 안전한 내부 `url(#id)` 참조는 허용한다.
- **로컬 접근:** 파일 하나를 선택한 권한을 주변 파일의 권한으로 확대하지 않는다. 이미지 접근 실패 위치에서 사용자가 `이미지 폴더 연결`을 선택했을 때만 시스템 폴더 선택을 시작한다. 선택한 폴더를 해당 문서의 기준 폴더로 삼고 그 아래 상대 경로만 해석한다. 문서별 연결과 폴더의 읽기 접근은 앱 재실행 후에도 유지한다.
- **경로 해석:** UTF-8 percent 인코딩을 한 번만 해석하며 공백·한글·중첩 하위 경로를 지원한다. `.`·`..`를 정규화한 결과가 기준 폴더 안이면 허용하고 밖으로 나가면 차단한다. 절대 경로와 `file:`·`content:` URI 및 허용하지 않은 URI는 차단한다. 차단된 경로의 권한을 자동으로 넓히지 않는다.
- **로컬 복구:** 잘못된 폴더·권한 거부/상실·파일 없음에는 해당 이유와 `이미지 폴더 연결`을 제공한다. 다시 연결한 폴더 기준으로 이미지를 다시 준비한다. 선택을 취소하면 기존 연결과 현재 본문을 유지한다. 파일 없음과 범위 밖/지원 밖 입력을 정상 표시로 간주하지 않는다.
- **웹 요청:** 문서에 포함된 HTTPS 이미지를 쿠키·인증 없이 자동 요청한다. HTTPS 사이의 리다이렉트만 최대 5회 허용하고 각 목적지에도 같은 URI 정책을 적용한다. HTTP와 기타 URI는 차단한다. 로컬 폴더 연결로 웹 오류를 복구하도록 안내하지 않는다.
- **처리 한계:** 로컬·웹 이미지 하나의 실제 입력은 **20 MiB**, 디코딩 결과는 **1,600만 픽셀**, 웹의 전체 요청 시간은 리다이렉트를 포함해 **20초**까지 허용한다. 한계 초과는 해당 이미지의 실패로 처리하고 일부를 잘라 성공으로 표시하지 않는다.
- **로딩·대체 설명:** 처음 준비 중인 이미지 영역은 스켈레톤으로 표시한다. 정상 그림과 실패 영역에는 Markdown alt를 대체 설명으로 사용하고 없으면 `이미지`를 사용한다. 실패에는 대체 설명과 실패 이유를 표시하며 접근성에도 같은 정보를 제공한다. 웹 오프라인·요청/디코딩 실패는 안내와 `다시 시도`를 제공하고 주변 본문을 유지한다.
- **캐시·갱신:** 디코딩 결과의 메모리 LRU 예산은 **64 MiB**, 웹 이미지 디스크 캐시 예산은 **100 MiB**다. 예산 안의 결과를 스크롤 재등장과 같은 이미지 확대에 재사용하며 예산 초과로 회수된 이미지는 다시 준비할 수 있다. 테마 변경은 원본 이미지를 재사용한다. 문서 원문·연결 폴더가 바뀌면 표시 요청을 갱신하고 이전 문서/폴더의 결과를 잘못 적용하지 않는다. 명시적 재시도는 메모리·디스크 캐시 읽기를 우회해 원본을 다시 읽으며 성공한 새 결과로 갱신한다. 일반 스크롤 중 외부 파일 변경을 자동 감시하지 않는다.
- **확대·탐색:** 정상 이미지 탭과 접근 가능한 그림 확대 동작으로 전체가 들어오는 맞춤 상태의 확대 화면을 연다. 맞춤 대비 **1–8배**에서 핀치 확대·축소와 팬을 제공한다. 하단에 확대·축소·맞춤 아이콘과 배율을 모으고 닫기는 상단에 둔다. `맞춤`은 초기 배율·위치를 복원한다. 닫기·시스템 뒤로는 확대 화면만 닫아 기존 본문 위치로 돌아가며 다시 열면 전체 맞춤으로 시작한다.

수용 기준:

- 지원한 다섯 형식별 실제 그림과 GIF 첫 프레임, 스크립트/외부 리소스 없는 SVG 및 지원 밖 입력을 확인한다. 정상 상태·뷰 크기만으로 성공을 판단하지 않고 실제 이미지 픽셀을 검사한다.
- 로컬 정상·중첩·공백/한글/percent 경로·내부로 정규화되는 `..`와 범위 밖/절대/금지 URI, 파일 없음·잘못된 폴더·연결 취소·권한 거부/상실을 fixture로 확인한다. 재실행 연결 유지와 실패 후 재연결·본문 유지를 검증한다.
- 웹 정상·로딩·오프라인·실패/재시도, HTTPS 리다이렉트 허용/초과/금지 목적지, 20 MiB·1,600만 픽셀·20초 경계를 검증한다. 웹 재시도와 로컬 폴더 연결이 구분되고 alt 없음도 접근 가능한지 확인한다.
- 스크롤로 화면 밖에 나갔다 돌아오는 흐름과 확대에서 캐시 재사용을 확인한다. 테마·문서 원문·폴더 연결 변경 및 명시적 재시도의 갱신 동작과 캐시 예산 회수를 검증한다.
- 그림 탭→맞춤→핀치/팬→맞춤 복원→닫기/시스템 뒤로→동일 본문 위치→재진입 맞춤을 검증한다. 좁은 폭·큰 글자·라이트/다크·접근성 대체 설명과 복구 행동을 확인한다.
- 재현 가능한 혼합 Markdown과 로컬 이미지 fixture를 `samples/`와 기기의 다시 선택 가능한 하위 폴더에 준비하고 실제 파일 선택→이미지 본문→연결/재시도→확대/복귀→홈을 확인한다. 필요한 최소 캡처로 그림 공백·잘림·대체 텍스트 오표시를 직접 점검하고 자동 검사와 구분해 기록한다. S07 캐시/확대·S06 수식·S05 코드 및 S02–S04를 영향 범위에서 회귀 검증하며 미검증은 구현 인계에 남긴다.

## 첫 범위

### 문법과 코드

- 기본 Markdown과 표·체크리스트·취소선·코드 블록, 수식, Mermaid 다이어그램 및 아래 채택한 확장 문법을 표시한다. CommonMark/GFM의 이번 확정 범위는 S03·S04, 코드 동작은 S05 프로필을 따르며, 수식은 S06 제한 프로필을 따른다. Mermaid는 S07 프로필을 따르며 그 밖의 예외는 미정이다.
- 코드 문법 강조와 코드 블록 복사 버튼을 제공한다. 긴 줄은 자동 줄바꿈하지 않고 블록 내부에서 가로 스크롤해 원래 코드 모양을 유지한다.
- 수식·Mermaid를 표시하지 못하면 해당 영역에 오류 안내와 원문 보기를 제공한다. 나머지 본문 읽기는 유지한다.

### 채택한 확장 문법

다음은 첫 버전에서 제공할 기능으로 채택했다. 서로 다른 방언을 하나의 표준으로 간주하거나 모든 변형을 무제한 지원한다는 뜻은 아니다. 실제 입력 표기법·지원 예외·호환 fixture를 정한 뒤 구현한다.

| 기능 묶음 | 채택 범위 | 구현 전에 정할 경계 |
| --- | --- | --- |
| 본문 보조 구조 | 각주·각주 목록, 정의 목록 | 참조·중복·순서 규칙과 이동 방식 |
| 인라인 표현 | highlight, 아래첨자·위첨자, 삽입·밑줄, emoji shortcode, typography 치환 | 구분자·사전·치환 규칙과 중첩 우선순위 |
| 문서 메타데이터 | YAML/TOML front matter | 인식 위치·구분자, 표시할 필드와 본문 노출 방식 |
| 제목·문서 연결 | heading ID/attribute list, wiki link, 문법 기반 자동 목차 | 허용 속성·ID 충돌·경로 및 링크 해석; 읽기 도구 목차와의 관계 |
| 콘텐츠 컨테이너 | 일반 callout/admonition, GitHub alerts, collapsible details | 방언·종류, 펼침 기본 상태와 접근성 |
| HTML·미디어 | HTML 블록·인라인 HTML, 미디어 임베드 | 허용 태그·속성·URL, 스크립트·외부 콘텐츠·로컬 접근·자동 재생 처리 |
| 학술·주석 | citation/bibliography, 주석 | 인용 키·참고문헌 데이터 형식·표시 및 주석 비노출 규칙 |

GitHub alerts와 mention·issue·commit 참조도 채택한다. 범위는 위에 나열한 Markdown 표현·참조이며 GitHub 제품 전체 기능을 뜻하지 않는다. 계정 인증·API·네트워크 요청·저장소 연동을 도입하는 결정은 별도다. 일반 callout/admonition과 GitHub alerts 표기법의 호환 fixture는 구분한다. 기존 GFM 표·체크리스트·취소선도 유지한다.

HTML·미디어를 채택해도 임의 스크립트 실행, 외부 요청·파일 접근·자동 재생을 허용한 것으로 해석하지 않는다. 구체 정책 결정 전에는 관련 제품 동작을 구현하지 않는다.

### 이미지와 확대

- 로컬 파일과 HTTPS 주소로 연결된 이미지를 S08+S09 확정 프로필에 따라 표시한다. 사용자 폴더 구조를 특정하지 않고 허용된 접근 범위 안에서 상대 경로를 처리한다.
- 이미지를 탭하면 확대 화면을 열고 두 손가락으로 확대·축소할 수 있다. Mermaid도 탭하면 확대해서 탐색할 수 있다.
- 문서를 열면 본문을 먼저 표시한다. 이미지 폴더 접근을 문서 열기의 선행 조건으로 요구하지 않는다.
- 접근할 수 없는 로컬 이미지 위치에 안내와 ‘이미지 폴더 연결’ 진입점을 표시한다. 사용자가 연결을 선택하면 폴더 선택을 시작한다.
- 연결하지 않거나 폴더 선택을 취소해도 본문 읽기를 유지한다. 웹 이미지 실패는 로컬 폴더 연결 흐름과 구분한다.

### 링크와 읽기 설정

- 웹 링크는 기본 브라우저로 연다.
- 다른 Markdown 문서로 연결되는 상대 경로 링크는 접근 권한이 있으면 MDive에서 연다. 대상에 접근할 수 없으면 실패를 안내하고 현재 문서를 유지한다.
- 앱의 라이트·다크 테마는 시스템 설정을 따른다.
- 본문 글자 크기를 조절하면 줄 간격도 본문 크기에 비례해 함께 조정한다.

## 수용 기준

- 합의한 세부 문법 범위의 예제 문서를 열면 기본 문법·표·체크리스트·취소선·코드 블록·수식·Mermaid 및 채택한 확장 문법을 표시한다. 각 채택 기능에는 정상·중첩·잘못된 입력·지원 밖 변형의 fixture와 기대 결과를 상세 명세 확정 시 작성한다.
- 각주·인용·문서 연결은 합의한 대상과 연결되고, 표시하지 못한 일부 콘텐츠 때문에 주변 본문 읽기가 중단되지 않는다. front matter·주석의 노출 여부와 실패 대체 표현은 해당 정책 확정 후 fixture로 검증한다.
- 지원 언어의 코드 문법을 강조하고 코드 블록 복사 버튼으로 해당 블록의 코드를 복사할 수 있다.
- 화면보다 긴 코드 줄은 원래 줄 구성을 유지하고 코드 블록 안에서 가로로 읽을 수 있다.
- 이미지 탭으로 확대 화면에 접근하고 두 손가락으로 확대·축소할 수 있다. Mermaid 탭으로 확대 탐색에 접근할 수 있다.
- 수식·Mermaid 표시 실패 시 해당 영역에 오류 안내와 원문 보기 진입점을 제공하며 나머지 본문은 읽을 수 있다.
- 로컬 이미지 접근이 불가능해도 읽을 수 있는 본문을 표시한다. 사용자가 ‘이미지 폴더 연결’을 선택했을 때 폴더 선택을 시작하며 취소해도 문서를 닫거나 본문 읽기를 차단하지 않는다.
- 웹 링크는 기본 브라우저로, 허용된 접근 범위의 상대 경로 Markdown 링크는 MDive로 연다. 상대 문서 접근 실패 시 안내하고 현재 본문을 유지한다.
- 시스템 테마에 맞는 라이트·다크 표현을 사용한다. 본문 크기 조절 시 줄 간격이 함께 비례 조정된다.

기존 화면 설계서의 밝은 배경은 라이트 모드 예시다. 별도 [제품 화면 시각 초안](../design/screens/index.html#reader)은 최신 DS의 다크 모드·크기 조절·수식·Mermaid·확대·오류 원문 보기와 확장 콘텐츠를 조합한다. 이 시각 초안은 동작 명세나 문법 호환 정책의 확정을 뜻하지 않는다. 시연 복사 버튼은 실제 클립보드를 변경하지 않는다.

## 열린 결정

- S03·S04에서 확정한 프로필 외 GFM 예외·채택 확장의 방언·구분자·중첩 규칙과 위 표의 기능별 경계, GitHub 참조의 owner/repository 문맥·대상 해석·문맥이 없는 로컬 문서의 처리. 인증·네트워크·실제 GitHub 연동은 별도 결정.
- HTML·미디어의 허용 태그·속성·URI·스크립트·외부 요청·파일 접근·자동 재생 정책.
- S06 제한 프로필 외 수식 명령·기능과 S07 프로필 밖 Mermaid 종류·기능.
- S08+S09 이미지 프로필 밖 형식·기능. 이미지의 경로·권한 복구·웹 요청/캐시·대체 설명·확대는 위 확정 프로필을 따른다.
- 문서 내부 제목 링크, Markdown 이외 파일·기타 URI 링크, 상대 문서 이동 후 돌아가기.
- 글자 크기 범위·단위와 줄 간격 비율·설정 진입점, 큰 문서·긴 표·접근성·태블릿의 기대 경험.

파서·권한 모델·저장 기술은 이 문서에서 선택하지 않는다. 제품 동작에 영향을 주는 미정 사항은 사용자와 합의하고 구현 구조는 관련 엔지니어링 문서에서 정한다.

## 화면 상태 표현 · 확정 방향과 검토안

읽기 화면 전체 로딩은 실제 본문 배치에 맞는 제목·문단 줄 스켈레톤으로 표현한다. 스켈레톤은 비상호작용 자리표시자이며 실제 파일명·본문을 준비된 예시 데이터로 채우지 않는다. 접근성 로딩 이름을 한 번 제공하고 장식 줄은 숨기며 모션 제한을 존중한다. 전체 스켈레톤과 본문 일부 이미지·수식·Mermaid 리소스의 준비 중 표시/복구 배너는 구분한다. 부분 리소스의 기존 진행 표시와 주변 본문 유지 원칙은 변경하지 않는다.

**검토안·승인 대기:** 빈 문서와 전체 열기 실패의 아이콘 타일을 없애고, 실패 이유와 재시도·홈 복귀 행동을 우선하는 구체 배치를 DS·디자인 보드에서 먼저 검토한다. 승인 후 제품 앱에 반영한다. 로딩 표시 시점·취소 제공 여부와 원인별 실패 문구 같은 미정 사항은 기존 결정 게이트에서 정한다.

## 디자인 리뷰 반영안 · 앱 적용 대기

읽기 기본 도구를 뒤로·제목·즐겨찾기·검색·더보기 한 행으로 조합한다. 더보기 버튼에 앵커된 우상단 팝업 메뉴의 첫 항목에 목차/책갈피를 두고 현재 위치 책갈피 추가·읽기 설정을 유지한다. 즐겨찾기는 상단 독립 토글로 제공하며 메뉴에 중복하지 않는다. 제목 앞 간격을 뒤보다 넓게 하고, 정상 렌더는 중립 표현, 지속 오류는 본문 공간을 확보하는 배너로 구분한다. 기능 삭제나 기존 열린 정책의 확정을 뜻하지 않으며 제품 앱은 이번 변경에 적용하지 않는다.
