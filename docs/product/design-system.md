# 디자인 시스템 · 편안한 심해

상태: 관리 방식과 `app`·`designsystem` 두 모듈 분리는 사용자 합의. 색상·크기·간격·컴포넌트 표현은 첫 검토용 초안이며 아직 시각 승인 전이다.

## 원본과 생성물

| 위치 | 책임 | 수정 방법 |
| --- | --- | --- |
| `design-system/tokens.json` | 테마별 라이트·다크 의미 색상, 간격, 글자 크기·행간, 글꼴 역할, 모서리의 공통 값 | 직접 수정 |
| `design-system/catalog.json` | 분류·목적·구성·변형·상태·동작·사용·접근성 지침과 공통 샘플 | 직접 수정 |
| `design-system/icons.json` | 공통 선형 아이콘의 24단위 경로·선 굵기 | 직접 수정 |
| `tools/generate_design_system.py` | Kotlin·CSS·HTML 생성과 최신 여부 검사 | 생성 규칙 변경 시 수정 |
| `design-system/components.css`·`feedback.css` | 카탈로그·제품 시각 초안이 직접 재사용하는 HTML 공통 외형·상태·글꼴 | 직접 수정, 공통 값은 토큰 참조 |
| `design-system/components.js` | 양쪽 HTML의 공통 배너 반응형 배치 | 직접 수정, 제품 행동·이동은 호스트 소유 |
| `design-system/catalog.css` | 카탈로그의 검토 컨트롤·설명·목록 배치 | 컴포넌트 외형을 덮어쓰지 않음 |
| `design-system/generated/` | HTML 카탈로그와 CSS 토큰 | 직접 수정 금지 |
| `designsystem/…/generated/` | Compose 토큰·카탈로그 목록·샘플 Kotlin | 직접 수정 금지 |
| `designsystem/src/main/`의 나머지 코드 | Compose 테마·글꼴·stateless 컴포넌트·카탈로그 표현 | 직접 수정, 생성된 값과 목록 사용 |
| 제품 Markdown | 사용 의도·합의 여부·검증 결과와 열린 결정 | 수치를 중복 표로 관리하지 않음 |

글꼴 선정과 라이선스 정책은 [타이포그래피](typography.md)를 따른다. 원본 값과 상태 목록은 양쪽 환경에서 공유하지만 HTML과 Compose의 실제 표현 코드는 각각 구현한다. 공통 JSON으로 플랫폼 UI 자체를 번역하는 프레임워크를 만들지 않는다. 상태가 추가되면 두 표현을 함께 갱신한다. 네이티브와 웹의 픽셀 일치를 보장하지 않으며, 역할·내용·상태와 읽기 경험을 검토한다.

현재 토큰은 카탈로그에 필요한 범위만 둔다. 새 규칙은 컴포넌트 검토를 거쳐 의미 있는 토큰과 자산으로 확장한다. 초안의 수치나 예시 문구를 제품 동작으로 확정하지 않는다.

## 생성·검사

저장소 루트에서 실행한다. Python 3 표준 라이브러리만 사용하며 별도 패키지 설치나 유료 서비스가 필요 없다.

```sh
python3 tools/generate_design_system.py
python3 tools/generate_design_system.py --check
./gradlew verifyDesignSystem
python3 -m unittest discover -s tools -p 'test_*.py'
```

생성 결과도 Git에 보관해 리뷰한다. 원본과 생성물이 다르면 `--check`가 실패한다. Gradle `preBuild`도 이 검사를 수행하므로 오래된 값으로 빌드하지 않는다. 재생성은 Python 명령 또는 `./gradlew generateDesignSystem`으로 명시적으로 수행한다. 생성기가 중복 카탈로그 ID와 테마별 색상 역할 불일치도 거부한다. 이 검사는 시각 검증을 대체하지 않는다. Compose 렌더러의 항목·상태 대응은 실제 카탈로그에서 함께 확인한다.

## 모듈과 실행

Gradle 모듈은 `app`과 `designsystem` 두 개다. `design-system/`은 플랫폼 공통 원본 폴더이며 세 번째 Gradle 모듈이 아니다.

- `designsystem`: Android 라이브러리. Compose 테마·재사용 컴포넌트·글꼴·생성된 값과 카탈로그 표현을 소유한다. 앱의 ViewModel·domain·data를 참조하지 않는다.
- `app`: 제품 진입점과 화면 MVI를 소유한다. 카탈로그 실행 Activity와 State·Intent·Effect·ViewModel은 `src/debug/`에만 둔다. 디자인 시스템 의존성은 카탈로그를 사용하는 debug 빌드에만 연결한다. 제품은 Compose 템플릿이며 release에 카탈로그를 연결하지 않는다.

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest
./gradlew :app:installDebug
adb shell am start -n com.parka.mdive/.catalog.CatalogActivity
```

`adb`가 PATH에 없다면 Android SDK의 `platform-tools/adb`를 사용한다. debug 앱 설치 후 앱 서랍의 **MDive 디자인 시스템** 아이콘으로도 열 수 있다. release에는 카탈로그 Activity와 해당 아이콘이 없다. 카탈로그의 테마 전환과 상태 비교는 검토 도구이며 제품에 테마 선택 기능을 추가하는 결정이 아니다.

## 카탈로그 읽는 방법

당근·토스의 [공식 사례 조사](design-system-references.md)를 바탕으로 기초 규칙과 컴포넌트를 나눈다. 목록에서 항목을 선택하면 목적 → 구성 → 변형·상태의 실제 예시 → 동작·사용 기준 → 접근성 지침 순으로 확인한다. 항목 메타데이터의 원본은 `catalog.json`이며 HTML과 Compose에서 함께 사용한다.

- **기초 규칙:** 색상, 타이포그래피, 간격·모서리, 아이콘.
- **컴포넌트:** 버튼, 공통 상단바, 문서 행, 한 줄 검색, 탭, 안내·상태, 코드·표 블록.

버튼은 외형 `primary/secondary/outlined/quiet`, 크기 `S/M/L`와 상태 `normal/pressed/disabled/loading`를 별개의 축으로 비교한다. 실제 누름·포커스·입력 차단은 실행 카탈로그에서 확인한다. 역할과 상태를 먼저 검토한 후 사용자 승인된 컴포넌트를 제품 화면에 조합한다. 사용자 검토 산출물은 실행 카탈로그이며 캡처를 기본 결과로 보여주지 않는다.

### 상단·하단 탐색 검토

공통 상단바는 화면 제목·선택적 탐색 버튼·액션 슬롯을 소유하는 stateless 컴포넌트로 제공한다. 기본·뒤로·액션·긴 제목 예시를 카탈로그에 둔다. 제목은 한 줄 말줄임과 전체 낭독 정보를 유지하고, 탐색·액션의 터치 영역은 고정한다. 시스템 바 여백은 화면 호스트가 처리한다. 카탈로그 헤더도 같은 상단바를 사용하며 제품 홈·읽기의 실제 도구 배치와 이동 정책은 아직 결정하지 않는다.

**앱 하단 탐색바는 현재 도입하지 않는다.** 확정된 주요 흐름은 홈에서 문서로 진입하는 구조이며, 하단에서 전환할 독립적인 최상위 목적지 여러 개가 없다. 목차·책갈피는 읽기 도구의 한 패널에 있는 두 탭으로 유지한다. 앞으로 독립 목적지가 생기면 필요성과 위치를 다시 검토한다. Android 시스템 탐색 영역(제스처·뒤로·홈)은 이 앱 컴포넌트와 별개이며 콘텐츠 가림과 밝기 대응을 유지한다.

타이포그래피는 9개 의미 역할을 글꼴·크기·굵기·행간 묶음으로 정의하며, 카탈로그에서 기준 sp 수치와 실제 예시를 함께 확인한다. 임의 비율로 파생하던 UI 제목·보조설명 크기는 제거했다. 상세 정책은 [타이포그래피](typography.md)를 따른다.

## 첫 검토 범위

### MDive 컴포넌트 구체화

Material의 기본 버튼·카드·칩·외곽선 입력창 외형을 그대로 사용하지 않는다. Compose Foundation의 입력·클릭·포커스·접근성 기능을 바탕으로 공통 외형과 상태를 정의하며, 텍스트와 테마 등 기본 렌더링 기반은 재사용한다. 사용자 검토 전인 첫 제안은 다음과 같다.

- 주 버튼은 부드러운 곡선과 미세한 색 깊이·윗면 경계를 검토하는 제안으로 두고, 보조 버튼은 옅은 면, 낮은 우선순위 동작은 배경 없는 텍스트로 구분한다. 누름·비활성·로딩을 함께 검토한다. 최소 터치 영역과 포커스·접근성 의미를 제공한다.
- 문서 목록은 개별 둥근 카드 대신 선과 여백으로 구분한다. 파일명·보조 정보·즐겨찾기를 다른 위계로 표시한다.
- 검색은 입력 영역만 옅은 채움과 둥근 경계로 감싸 입력창임을 구분하고, 포커스 시 경계를 강조한다. 종료·입력·결과 건수·이전/다음 한 줄 계약을 유지한다. 카탈로그에서 입력 전·결과 있음·없음 예시를 직접 편집할 수 있으며 결과 건수는 시연 값이다.
- 아이콘은 공통 경로 원본에서 Compose와 HTML로 생성한다. 24단위 좌표계와 둥근 선 끝을 사용하며 선택·상태를 색상만으로 전달하지 않는다.
- 목차·책갈피 탭은 얇은 선택 표시로, 로딩·빈 상태·오류는 아이콘·제목·설명 위계로 표현한다. 미정인 패널 형태나 복구 동작을 제품 결정으로 취급하지 않는다.
- 홈·읽기 화면은 이번 카탈로그에서 제외한다. 파일·검색·저장 버튼은 컴포넌트 조작 예시이며 실제 제품 동작을 수행하지 않는다.

최종 치수와 상태 표현은 카탈로그에서 검토하며, 공통 값은 토큰 원본으로 관리한다. 미작성 설정·확대·저장 실패 등은 이후 확장 범위다.

사용자 피드백에 따라 모서리를 조금 더 둥글게 하고 구분선과 누름 효과를 완화했다. 모서리와 상태 투명도는 `tokens.json`의 `radii`·`opacities`를 원본으로 HTML·Compose에 함께 반영한다. 세 색상안과 글꼴은 유지한다.

색상안은 **심해**, **청량한 바다**, **편안한 초록** 세 가지다. 카탈로그 상단에서 색상안을 바꾸고 라이트·다크를 독립적으로 비교한다. 공통 원본 `themes`의 ID·이름·색상에서 Kotlin 테마 목록과 CSS·HTML의 여섯 조합을 생성한다. 글꼴과 배치는 같게 유지한다. 선택은 카탈로그 메모리 안에서만 유지하며 제품 테마 설정·영속 저장 정책을 추가하지 않는다.

- 라이트·다크 의미 색상과 Pretendard 본문·제목·UI와 JetBrains Mono 코드.
- 버튼 정상·비활성, 문서 목록 정상·빈 상태·오류 표현.
- 한 줄 검색바의 결과 있음·없음 예시.
- 독립된 코드·표 컴포넌트 예시.

실제 문서 파싱·파일 선택·검색·저장·네트워크를 구현하지 않는다. 공통 컴포넌트를 검토한 뒤 홈·읽기 화면을 구체화하고, 승인된 규칙을 바탕으로 설정·책갈피·확대·오류 상태를 확장한다.

시각 검증은 사용자 합의에 따라 Compose 카탈로그에서 진행한다. [생성 HTML 카탈로그](../../design-system/generated/catalog.html)는 같은 원본을 검토하는 보조 산출물이며 브라우저 검증 완료를 뜻하지 않는다. 외부 배포는 하지 않는다.

## 컴포넌트 카탈로그 검증 · 2026-10-26

- debug 카탈로그를 에뮬레이터에 설치·실행했다. 기초 규칙/컴포넌트 목록과 개별 상세 가이드를 제공하고 제품 홈·읽기 시안은 제외했다.
- 빌드·단위 테스트·생성 검사 통과. 기기 테스트에서 목록→상세, 테마·밝기 유지, 검색 한 줄, 탭 선택, 코드·표 가로 스크롤, 일반 버튼 실행과 비활성·로딩 입력 차단을 확인했다. 추가 회귀 테스트에서 상세의 시스템 뒤로 가기가 목록으로 돌아오고 Activity가 유지됨을 확인했다.
- 생성기 회귀 테스트 7개 통과. 공통 아이콘 선 굵기와 타이포그래피 크기·행간 변경도 Kotlin과 CSS 양쪽에 반영된다.
- HTML의 로컬 링크·고유 ID·anchor·스크립트 구문과 컴포넌트 전용 목록을 정적으로 확인했다. 브라우저 렌더는 검증하지 않았다.
- 포커스 대비·코드 위 복사 아이콘 대비·문서 행 포커스 표시를 독립 검토에서 수정했다. 전체 TalkBack·큰 글자·다른 기기 검증은 남아 있으며 사용자 시각 승인은 아직 받지 않았다. 캡처를 이번 검토 결과로 제시하지 않는다.
- 후속 입력·모서리 조정 후 빌드·단위 테스트와 기기 테스트 8개가 통과했다. 좁은 폭에서 검색 입력의 포커스·편집·결과·이동 버튼 표시, 긴 상단바 제목의 접근성 원문과 액션 콜백도 확인했다. 카탈로그를 에뮬레이터에 재설치·실행했다.

## 브랜드 아이콘과 최종 검증 · 2026-10-26

사용자가 승인한 앱 아이콘과 UI 대표 심볼은 [브랜드 원본](../../design-system/brand/README.md)을 따른다. `MDiveBrandMark`는 런처 배경과 분리되어 상단바의 `leading` 슬롯 등에서 재사용할 수 있다. 아이콘 카탈로그에 테마색과 원색 예시를 함께 제공한다.

- 공통 카탈로그와 런처 리소스 생성 검사가 Gradle `preBuild`에서 수행된다.
- 최종 debug 빌드·단위 테스트·release manifest 처리와 Python 생성기 회귀 테스트 7개가 통과했다.
- Pixel 3 API 30 에뮬레이터의 전체 기기 테스트 12개가 통과했다. 컴포넌트 입력·비활성·로딩, 검색·타이포그래피·탭·목록/상세 복귀, 런처 안전 영역·원형 마스크·단색·구형 벡터 렌더링을 검증했다.
- Android 24~25 실제 기기 및 Android 33 이상 런처의 자동 테마 색상은 아직 검증하지 않았다. 구형 일반/원형 리소스와 단색 전경은 API 30에서 직접 렌더링해 확인했다.
- HTML 브라우저 렌더, 전체 TalkBack·큰 글자·태블릿 검증은 남아 있다. 디자인 카탈로그는 검토용 초안이며 브랜드 아이콘 선택과 별개로 전체 컴포넌트 디자인의 최종 승인을 뜻하지 않는다.

## 공통 컴포넌트 보완

제품 화면을 다시 디자인하기 전에 아래 공통 컴포넌트를 추가·검토한다. 화면 배치와 데이터 정책은 제품 명세에서 결정하며, 카탈로그 예시가 이를 대신 확정하지 않는다. 추가분의 커밋·푸시는 사용자 검토 후 요청에 따라 진행한다.

| 영역 | 기존 상태 | 이번 보완 |
| --- | --- | --- |
| 버튼·아이콘·상단바·문서 행·검색·탭 | 기존 공통 API 있음 | 재사용 |
| 빈 상태·전체 실패·부분 실패 | 같은 안내 행에 의존 | 상태 패널과 인라인 안내를 분리 |
| 목록 제거 확인 | 전용 컴포넌트 없음 | 확인 다이얼로그: 기본·긴 설명·처리 중 |
| 현재 화면의 연관 도구 | 탭만 있음 | 바텀시트: 기본·긴 본문 스크롤 |
| 짧은 완료 알림 | 전용 컴포넌트 없음 | 토스트형 완료/정보 안내 |
| 복구 행동이 필요한 실패 | 전용 컴포넌트 없음 | 본문을 유지하는 복구 배너 |
| 책갈피 이름 같은 입력 | 검색 전용 입력만 있음 | 공통 입력: 기본·오류·비활성 |
| 본문 크기 같은 범위 조절 | 전용 컴포넌트 없음 | 슬라이더: 기본·비활성, 키보드·접근성·RTL |

디자인 원칙:

- 정상적인 빈 상태에 경고색·실패 문구를 쓰지 않는다.
- 문서를 전혀 읽을 수 없는 실패는 전체 상태로, 일부 리소스 실패는 해당 영역 안에서 표시한다.
- 다이얼로그는 확인이 필요한 결정에 사용한다. 목록 제거는 원본 파일 삭제와 구분해 안내한다.
- 복구 행동이 필요한 실패를 금방 사라지는 토스트로 처리하지 않는다. 토스트 시간·대기열·배너 유지 정책은 호스트가 소유한다.
- 바텀시트는 Material3 `ModalBottomSheet`를 기반으로 열기·닫기 전환과 아래로 드래그해 닫기를 제공한다. 제목은 가운데 고정하고 본문만 스크롤하며, 기본값은 중간 높이를 생략한다. 닫기 전환 완료 후 호스트에 제거를 요청한다.

공통 원본은 `tokens.json`·`catalog.json`이며 HTML은 `components.css`·`feedback.css`, Compose는 `Feedback.kt`·`Overlays.kt`·`Inputs.kt`가 표현을 담당한다. 카탈로그의 **치수·토큰** 절은 token reference에서 실제 dp/sp 값을 계산해 양쪽에 생성하므로 수치를 화면 문서에 복제하지 않는다.

검토 순서: 빈/실패 상태 → 확인 다이얼로그 → 바텀시트 → 토스트/복구 배너 → 입력/슬라이더. 세 색상안과 라이트·다크를 독립적으로 비교할 수 있다. 확인 다이얼로그의 버튼은 긴 라벨·큰 글자를 수용하도록 세로로 배치했다. 표시 위치·치수는 이번 검토 대상이다.

### 추가분 검증

- `:designsystem:assembleDebug`, `:app:assembleDebug`, `:app:testDebugUnitTest` 통과. debug 카탈로그를 API 30 에뮬레이터에 설치·실행했다. 제품 앱은 기존 템플릿 상태다.
- DS 기기 테스트 7개와 기존 앱/카탈로그 기기 테스트 12개가 통과했다. 다이얼로그 확인·뒤로·바깥 탭·처리 중 입력 차단, 큰 글자와 긴 설명, 바텀시트 닫기, 슬라이더 실제 탭/드래그·비활성·RTL·접근성 입력을 확인했다.
- Chrome에서 신규 7개 카탈로그 항목을 3개 폭(1440/390/320)·3개 색상안·라이트/다크의 126개 조합으로 확인했다. JS·리소스 오류와 문서 가로 넘침이 없었다. 다이얼로그 반복 Escape 차단·긴 설명 스크롤, 시트 스크롤/닫기, 입력과 슬라이더의 값/활성 구간을 확인했다.
- 독립 검토에서 발견한 HTML 처리 중 다이얼로그의 반복 Escape 종료와 슬라이더 활성 구간 표시 불일치를 수정했다. 레이블/현재 값의 타이포그래피도 Compose 역할과 맞췄다.
- 생성 검사·생성기 회귀 테스트 8개·문서 링크·diff 검사가 통과했다. 추가 치수의 토큰 변경이 CSS와 양쪽 카탈로그의 치수 설명까지 전파됨을 검사한다.
- 전체 TalkBack·다른 Android 버전·태블릿 검증은 남아 있다. 제품 화면 적용은 후속 화면 디자인 검토 뒤 진행한다.

### 바텀시트 사용성

`Dialog`로 하단 위치만 표현하는 방식 대신 Material3 `ModalBottomSheet`의 모션·제스처·모달 처리를 사용하고 표면색·모서리·간격·타이포그래피는 MDive 토큰으로 적용한다. 콘텐츠 안에서 항목을 선택해 닫을 때도 제공된 `requestDismiss` 콜백으로 내려가는 전환을 거친다. HTML 카탈로그는 열기·닫기 전환, 핸들 드래그와 모션 감소 설정을 시연하며 Android의 실제 사용성은 Compose 카탈로그에서 확인한다.

API 근거: [Android Bottom sheets](https://developer.android.com/develop/ui/compose/components/bottom-sheets). `SheetState.hide()` 완료 후 composition에서 제거하는 생명주기를 따른다.

### 복구 배너 배치

재시도 예시는 짧은 메시지와 오른쪽 outlined S 동작을 같은 행에 배치한다. 보조설명은 선택적이며 없는 설명이나 동작을 위한 빈 공간은 만들지 않는다. 큰 글자·좁은 폭에서는 내용과 겹치지 않도록 복구 동작만 아래 오른쪽으로 옮긴다. 분기 기준은 공통 토큰의 폭과 글자 배율을 함께 적용한다. 복구 동작과 닫기는 별도 콜백이며 카탈로그의 예시 동작은 실제 저장을 하지 않는다.

### 바텀시트·복구 배너 재검증

- Material3 기반 바텀시트의 실제 진입/퇴장 위치 변화, 전환 중 호스트 유지, 중복 닫기 콜백, 아래 드래그·재열기·시스템 뒤로를 기기 테스트로 확인했다.
- 배너의 메시지·오른쪽 재시도 정렬, 큰 글자/좁은 폭의 아래 오른쪽 배치, 동작 없는 배너의 빈 영역 부재를 확인했다. 경고 아이콘 색·텍스트 역할·시트 핸들 터치 영역을 HTML/Compose에 맞췄다.
- DS 빌드와 API 30 기기 테스트 12개가 통과했다. HTML의 진입·퇴장 애니메이션, 핸들 드래그·닫기·재열기·Escape·모션 감소, 배너 정렬·큰 글자·재시도·닫기 및 126개 테마/폭 조합도 확인했다. 제품 화면 적용은 후속 작업이다.

## 제품 화면 조합 · 2026-10-27

[제품 시각 초안](../design/screens/index.html)은 PR #9의 데이터 기반 Markdown 콘텐츠 API와 기존 도구·상태 컴포넌트를 조합한다. 제품의 동작 명세는 `docs/product/`가 소유하며, 카탈로그와 시각 초안은 문법 방언·접근·저장·복구 정책을 결정하지 않는다. 홈·읽기 제품 Android 화면·파서·로더·렌더 엔진은 이번 조합에 포함하지 않는다. 기존 절의 “후속 제품 적용”은 Android 제품 구현을 가리키며 HTML 시각 초안의 존재와 구분한다.

### 안내 내부 정렬 보정

제품 화면 검토 피드백에 따라 `MDiveInlineNotice`의 아이콘·로딩 표시를 텍스트 묶음의 세로 중앙에 배치한다. HTML `feedback.css`와 Compose `Feedback.kt`를 함께 수정했으며, 제품 시각 초안은 안내 내부 문단이 문서 전체의 아래 간격을 상속하지 않도록 분리한다. 생성 검사와 `:designsystem:compileDebugKotlin`은 통과했으며 이번 정렬 변경의 실제 HTML/Compose 렌더는 재검증하지 않았다.

### 버튼 타입과 크기

외형과 크기는 독립적인 축이다. secondary에 임시로 추가했던 경계는 제거하고, 경계가 필요한 행동은 명시적인 outlined로 구분한다. 이번 타입·크기 배치는 시각 초안이며 제품의 복구·저장 정책은 변경하지 않는다.

| 타입 | 표현 | 사용 예 |
| --- | --- | --- |
| Primary | 강조 채움 | 홈 파일 열기, 주요 확인 |
| Secondary | 옅은 채움, 경계 없음 | 배경과 구분되는 일반 보조 행동 |
| Outlined | 투명 배경과 얇은 경계 | 색이 있는 배너 안 원문 보기·복구 행동 |
| Quiet | 무배경, 누름·포커스 때 영역 표시 | 취소·닫기·낮은 우선순위 도구 |

| 크기 | 가시 면의 기본 최소 높이 | 적용 예 |
| --- | --- | --- |
| S | 36dp | 배너 안 행동·읽기 도구 |
| M | 40dp | 일반 행동·기본값 |
| L | 48dp | 홈 파일 열기·주요 행동 |

가시 면과 터치 영역은 구분한다. 모든 크기는 최소 48dp 터치 영역을 확보하고, 라벨과 아이콘을 가시 면 중앙에 배치한다. 큰 글자·여러 줄 라벨은 면 높이와 터치 영역이 함께 늘어나며 고정 높이로 자르지 않는다. 화면에서 터치 영역을 겹치게 조밀하게 배치하지 않는다. 좌우·상하 여백과 높이는 공통 토큰을 사용하고, quiet도 여백을 없애지 않는다. 본문 텍스트 링크는 버튼 크기와 별개다.

실제 API는 `MDiveButtonVariant`와 `MDiveButtonSize`를 받고, HTML은 `outlined` 및 `size-s/size-m/size-l` 클래스로 대응한다. 생성 카탈로그와 Compose 카탈로그에서 타입 × 크기 × 상태를 비교한다. 생성 파일은 직접 수정하지 않는다.

### Pressed 색상 기준

버튼의 pressed는 모든 테마에서 같은 투명도만 섞는 방식 대신 타입·바탕에 맞는 공통 의미 색으로 관리한다. 일반 버튼은 라이트에서 어두워지고 다크에서 밝아지는 방향으로 통일하며, secondary·outlined·quiet·아이콘 버튼은 일반 바탕과 배너 바탕 모두에서 면의 변화가 드러나야 한다. 코드 복사처럼 항상 어두운 코드 면 위의 행동은 별도 코드 면 상태색을 사용한다.

카탈로그의 고정 pressed 예시와 실제 누르는 동안의 색을 동일하게 적용한다. S/M/L은 같은 상태색을 공유하고, disabled·loading에서 누름색이 나타나지 않도록 입력 차단을 유지한다. 라벨 대비와 기본/누름 면의 변화는 별도로 분석하며, 면의 색차 수치는 MDive 검토 기준이지 접근성 표준의 상태 간 대비 의무를 뜻하지 않는다. 실제 기기·밝기·사용자의 인지 검토는 수치 비교와 구분한다.

공통 색은 `buttonPressedPrimary`·`buttonPressedSurface`·`buttonPressedText`·`buttonPressedCode`로 관리한다. primary는 라이트에서 검정 16%, 다크에서 흰색 35%를 섞어 확정 RGB를 원본에 기록했다. 보조·outlined·quiet·일반 아이콘의 pressed 면은 surfaceVariant에 onSurface를 라이트 16%·다크 20% 섞고, 글자도 전용 pressed 전경으로 전환한다. 코드 면은 페이지 밝기와 관계없이 어두우므로 밝아지는 상태색과 codeText를 유지한다. HTML/Compose 모두 같은 토큰을 소비한다.

### 배너·바텀시트 공통 구성

- 복구 배너는 기본적으로 메시지 **오른쪽 행동 영역**을 사용한다. 행동이 두 개면 그 영역 안에서 세로로 쌓으며, 좁은 폭·큰 글자일 때만 기존 기준대로 아래 오른쪽으로 이동한다. 설명 안에 버튼을 직접 삽입하지 않는다. HTML과 Compose의 공통 배너·카탈로그·제품 시각 초안 모두 같은 규칙을 사용한다.
- 바텀시트는 제목을 가운데 두고 제목 아래 장식 구분선과 X 버튼을 제거한다. 제목·핸들은 고정하고 본문만 스크롤한다. 아래 드래그·바깥 탭·시스템 뒤로의 닫기 전환을 유지하며 핸들에도 레이블 있는 키보드/접근성 닫기 동작을 둔다. 탭 자체의 선택 표시나 목록 구분선과 제목 아래 장식선은 구분한다.

바텀시트 핸들의 시각 여백은 공통 `spacing.sheetHandleY`로 상하 6dp씩 적용한다. 4dp 선을 포함해 핸들 영역의 시각 높이는 16dp이며, 기존 48dp 높이의 빈 공간을 줄인다. 시트 전체 드래그와 핸들의 접근성 닫기 동작은 유지한다.

### 제품 화면의 DS 재사용 경계

카탈로그와 제품 시각 초안은 `components.css`·`feedback.css`·`components.js`를 직접 공유한다. 제품 HTML이 카탈로그 페이지 전체 CSS에 의존하거나 비슷한 외형을 화면별로 다시 작성하지 않는다. 같은 클래스라도 내부 구조가 다르면 상태·색·여백이 어긋날 수 있으므로 코드 헤더·표·문서 행·시트·다이얼로그도 공통 HTML 계약으로 조합한다.

제품의 `screens.css`는 화면 배치·스크롤·오버레이 위치, 검토 도구, 실제로 화면 전용인 목차·책갈피 행과 준비된 그림 내부 표현만 소유한다. 버튼·검색·탭·문서 타이포·배너·입력·시트의 색·글꼴·내부 여백·모서리·상태를 여기서 덮어쓰지 않는다. 공통 변경은 DS 원본과 카탈로그에서 처리한다. 대응표와 허용한 화면 전용 영역은 [컴포넌트 사용 기준](../design/screens/component-usage.md)을 따른다.

`tools/test_screen_component_contracts.py`는 같은 렌더러 참조, 공통 마크업 구조·아이콘 원본 일치, 제품 CSS의 공통 외형 덮어쓰기 방지를 검사한다. 이는 실제 브라우저·Android 렌더 검증과 별개다. 이번 공유 HTML 정리는 Compose의 기존 API를 대조했으며 Android 제품 화면을 구현하지 않았다.
