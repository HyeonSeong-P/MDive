# MDive 제품 방향

상태: 첫 버전 범위와 홈·읽기 기본 방향 합의. 최신 DS·제품 시각 초안과 세션별 구현 계획을 정리했으며 제품 Android는 S02의 시스템 파일 선택·제목·원문 로더까지 연결했다. 파싱·최종 본문 표시는 후속 단계다. 전체 디자인의 시각 승인과 미정 정책의 확정은 구분한다.

## 대상 사용자와 목표

Markdown 문서를 자주 작성하고 읽는 사람이 모바일에서 문서를 편하게 읽을 수 있는 Android 뷰어를 만든다. 본문은 책처럼 편안하게, 코드와 표는 개발 문서처럼 명료하게 표현한다.

출발점은 공부하며 PC 로컬 폴더와 Git 프로젝트에 작성한 문서다. 사용자는 아직 휴대폰에서 읽는 과정을 시도하지 않았으므로, 기존 모바일 앱의 구체적인 사용성 문제는 검증되지 않았다. PC에서 휴대폰으로 파일을 전달하는 방법도 아직 정하지 않았다.

## 핵심 시나리오

1. 홈에서 Markdown 파일 하나를 선택하고 렌더링된 문서를 읽는다.
2. 코드·표·체크리스트·이미지·수식·Mermaid와 각주·참고문헌 등 확장 콘텐츠를 확인하고, 필요한 내용을 검색하거나 목차로 이동한다.
3. 자주 볼 문서는 즐겨찾기에, 다시 볼 문서 안의 위치는 책갈피에 저장한다. 다음에 문서를 열면 읽던 위치에서 이어 읽는다.
4. 로컬 이미지나 문서 링크에 접근할 수 없더라도 현재 본문 읽기를 유지하며 필요한 접근을 연결한다.

## 첫 버전 범위와 명세 원본

| 영역 | 합의한 범위 | 상세 정책·수용 기준 |
| --- | --- | --- |
| 홈 | 파일 하나 열기, 위쪽 즐겨찾기, 최근 문서, 첫 실행 안내, 파일 접근 실패 시 파일 다시 연결·목록 제거 | [홈과 문서 바로가기](home.md) |
| 문서 표시 | 기본 Markdown·GFM 표현과 채택한 확장 문법, 수식·Mermaid, 코드 강조·복사·가로 스크롤, 이미지·Mermaid 확대 | [문서 표시와 읽기 설정](document-viewing.md) |
| 파일·링크 | 로컬·웹 이미지, 필요한 이미지 위치에서 폴더 연결, 웹 링크는 브라우저로 열기, 접근 가능한 상대 경로 Markdown은 앱에서 열기 | [문서 표시와 읽기 설정](document-viewing.md) |
| 읽기 설정 | 시스템 라이트·다크 테마, 본문 글자 크기 조절과 줄 간격 비례 조정 | [문서 표시와 읽기 설정](document-viewing.md) |
| 읽기 도구 | 상단 한 줄 검색바, 목차·책갈피 탭, 읽던 위치 기억, 문서별 여러 위치 책갈피 | [읽기 도구](reading-tools.md) |

즐겨찾기와 책갈피는 기기 내에 저장해 앱 재실행 후에도 유지한다. 저장 기술은 구현 단계에서 선택한다. 사용자 폴더 구조를 특정하지 않고 허용된 접근 범위 안에서 상대 경로를 처리한다.

폴더 안 문서 탐색, Git 저장소 연결, Markdown 편집은 이후 확장 후보다. 내보내기는 포함 여부가 미정이다.

문법 범위는 [문서 표시 명세의 채택 목록](document-viewing.md#채택한-확장-문법)을 따른다. 2026-10-27 합의로 확장 문법의 기능 채택 범위를 넓혔다. 정확한 방언·표기법·호환 버전과 HTML·미디어 처리 정책은 별도 결정하며, 채택은 구현 완료를 뜻하지 않는다. GitHub alerts와 mention·issue·commit 참조도 채택한다. 이는 이번에 나열한 Markdown 표현·참조의 지원이며 GitHub 제품 전체 기능이나 계정·저장소 연동을 뜻하지 않는다. 기존 GFM 표·체크리스트·취소선은 유지한다.

## 구현 재개 범위와 진행 방식

홈에서 파일 하나를 선택해 본문을 읽는 첫 흐름을 먼저 구현하고, 홈 이력·즐겨찾기·읽기 도구는 별도 단계로 연결한다. 첫 버전의 채택 범위는 축소하지 않는다. 기존 stash에 보관했던 2026-10-26 합의는 다음과 같이 복원한다.

- 파일 선택 취소는 홈 유지, 홈에서 직접 연 문서의 상단 뒤로·시스템 뒤로는 홈 복귀다. 일반 문서 열기 실패는 읽기 화면에서 재시도·홈 복귀를 제공한다. 기존 문서 바로가기의 접근 실패는 홈에서 파일 다시 연결·목록 제거·닫기를 제공하며 구분한다.
- 수식은 `$…$`·`$$…$$`, Mermaid는 `mermaid` 코드 블록을 사용한다. 세부 명령·기능·지원 종류와 호환 버전은 미정이다.
- 이미지 접근 실패 위치에서 연결한 폴더를 문서 기준 폴더로 해석해 하위 상대 경로를 읽고 연결을 재실행 후에도 유지한다. 허용 범위 밖 경로·잘못된 연결·권한 상실 복구는 미정이다.
- 웹 이미지는 온라인에서 읽고 실패 시 본문 유지·재시도를 제공한다. 오프라인 안내·대체 텍스트 등 상세는 미정이다.
- 홈의 기존 문서 바로가기 접근 실패는 홈 목록을 유지한 채 복구 다이얼로그로 안내한다. 홈 목록 제거는 취소·제거를 선택하는 별도 확인을 거치고 원본 파일을 삭제하지 않는다. 재연결·동일 문서 판별·관련 정보 보관은 미정이다.

구체 동작은 [홈](home.md)·[문서 표시](document-viewing.md)에 반영한다. 과거의 “DS 보완 후 화면을 다시 작성할 때까지 중단” 상태는 이번 디자인 갱신 이전의 기록이며 현재 작업 제한으로 복원하지 않는다. 다음 구현은 [세션별 계획](../implementation/open-markdown.md)의 요청받은 ID 하나만 수행하고 멈춘다. S01은 DS 첫 실행 홈·읽기 상태 호스트 및 Hilt·Navigation 3 연결까지 제공하며, S02는 실제 시스템 파일 선택과 원문 읽기를 연결하고 제품에는 파일명·중간 안내를 표시한다. 최종 Markdown 본문은 후속 단계다.

## S02 로더 경계 · 2026-10-27 확정

S02는 시스템 파일 선택과 제목·원문 읽기까지만 구현한다. UTF-8(선두 BOM 허용)과 BOM으로 식별되는 UTF-16 LE/BE를 지원하고, 잘못된 인코딩은 열기 실패로 처리한다. 파일 상한은 실제 입력 바이트 기준 5 MiB다. 파일 전체를 선택기에 표시하되 `.md`·`.markdown`·`.txt`만 허용한다. 상세 정책과 수용 기준은 [문서 표시](document-viewing.md#s02-로더-경계--확정)가 소유한다. 파서와 최종 본문 표시는 S03 이후 범위이며 S02 성공을 Markdown 지원 완료로 표시하지 않는다.

## 승인된 화면 방향

- [S-01 읽기](screens/reader.html#s-01): 본문·코드·표·이미지의 기본 표현 방향을 사용자 검토 후 채택했다. 검색은 상단 한 줄에 입력 필드·`1/3`·이전/다음 버튼을 묶는 구성으로 합의했다.
- [S-02 홈](screens/home.html#s-02): 파일 열기, 위쪽 즐겨찾기, 최근 문서와 첫 실행 안내의 기본 구성을 사용자 검토 후 채택했다.

아래에 별도로 합의한 브랜드 표시와 화면 여백 외의 색상·글꼴·간격 세부 값, 샘플 문구·데이터와 시안의 미정 표시는 확정 요구사항이 아니다. HTML은 동작을 검토하는 화면 설계서이며 앱 구현 코드가 아니다.

## 디자인 검토 반영안 · 앱 적용 대기

사용자가 두 차례 디자인 리뷰의 반영 작업을 승인했다. 아래는 디자인 화면과 DS에서 구체화하는 배치 검토안이며, 제품 앱 적용과 미정 행동 정책의 확정은 별도다.

- 재방문 홈은 큰 환영 영역을 줄이고 즐겨찾기·최근 문서를 먼저 보여준다. 문서가 있는 홈의 파일 열기는 우하단 FAB로 옮기며 상단 버튼을 중복 제공하지 않는다. 첫 실행은 승인된 문서 퐁당 일러스트와 내용 폭의 L 파일 열기, 빈 상태의 단일 복구는 내용 폭의 M 버튼을 사용한다.
- 읽기 기본 도구를 한 상단 행으로 모은다. 뒤로·문서 제목·즐겨찾기·검색·더보기를 항상 제공한다. 더보기는 버튼에 앵커된 우상단 팝업 메뉴이며 목차/책갈피를 첫 항목으로, 현재 위치 책갈피 추가·읽기 설정을 이어 제공한다. 즐겨찾기는 독립 토글로만 제공해 메뉴에 중복하지 않는다. 기능을 삭제하거나 도구 자동 숨김을 추가하지 않는다.
- 일반 전체 열기 실패는 primary 재시도와 quiet 홈 복귀만 제공한다. 다시 선택은 일반 오류에서 제거하고, 기존 홈 문서의 접근 복구는 `파일 다시 연결`이라는 별도 맥락으로 구분한다.
- 본문 제목 앞 간격은 뒤보다 넓게 두어 제목을 다음 문단과 묶는다. 정상 렌더 상태는 중립적으로 표현하고, 지속 오류 배너는 본문을 덮지 않게 문서 흐름 안에서 공간을 확보한다. 일시 완료 토스트만 겹쳐 표시한다.
- 한 줄 검색의 48dp 터치 영역과 기본 좌우 16dp를 유지하면서 중복 패딩을 줄인다. 시트 본문도 호스트와 자식의 중복 16dp 여백을 제거한다.

## 디자인 방향과 관리 합의

- 시각 방향은 **편안한 심해**다. 본문은 책처럼 편안하게, 코드와 표는 개발 문서처럼 명료하게 표현한다는 기존 기준을 유지한다. 구체적인 색상·글꼴과 아래 기본 여백 외의 간격은 아직 미정이다.
- **확정 방향:** 화면 전체 로딩은 각 화면 구조에 맞는 스켈레톤으로 표시한다. 구체적인 막대 수·폭·배치는 DS·디자인 보드에서 검토한 뒤 제품 앱에 반영한다. 홈은 목록 제목·문서 행, 읽기는 본문 제목·문단 줄의 비상호작용 자리표시자를 사용한다. 접근성에는 로딩 상태 이름을 한 번 제공하고 장식 막대는 숨긴다. 모션은 필수가 아니며 모션 제한 설정을 존중한다. 본문 일부 이미지·렌더 리소스의 준비 중 표시와 복구 배너는 유지한다.
- **일러스트 확정:** 사용자 승인 ImageGen 단색 PNG에서 자동 트레이스한 정적 ‘문서 퐁당’ 일러스트를 디자인 화면과 DS 카탈로그에 사용한다. 공통 원본은 `design-system/illustrations/document-plunge.svg`이며 임의로 다시 그리지 않는다. 세 색상안의 라이트·다크에서 primary 색으로 표시한다. 이 승인은 일러스트 자체에 한정하며 첫 실행의 구체 배치·문구, 스켈레톤의 구체 배치, 빈/실패 개편 전체 승인이나 제품 앱 적용 완료를 뜻하지 않는다.
- **검토안·승인 대기:** 첫 실행 홈의 사각 배경 문서 아이콘을 없애고 짧은 환영 문구·파일 열기와 승인된 문서 퐁당 일러스트로 구성하는 안, 빈 문서·전체 실패의 아이콘 타일을 없애고 이유·복구 행동을 우선하는 안을 DS·디자인 보드에서 먼저 검토한다. 구체 배치의 사용자 결정 후 제품 앱에 반영하며, 이번 시안 작성은 앱 적용 완료를 뜻하지 않는다. 문서가 물에 들어가는 모션·GIF·Lottie와 새 의존성은 이번 변경에 도입하지 않는다.
- 홈 상단바는 기존 브랜드 아이콘으로 앱을 식별하며 `MDive` 글자를 나란히 반복하지 않는다. 아이콘에는 접근성 이름 `MDive`를 제공한다. 읽기 화면의 문서 제목·뒤로·도구는 유지한다.
- 앱 화면의 기본 좌우 여백은 **16dp**다. 본문 영역의 위아래 시작·끝 여백도 **16dp**를 기본으로 한다. 상태 화면은 가용 영역 중앙 배치를 유지하면서 가장자리 여백을 확보한다. 상단바 높이·48dp 터치 영역·시스템 인셋과 버튼·코드·표 등 컴포넌트 내부 여백, 목차 깊이와 전체 폭 시트 같은 의미 있는 예외는 각각의 DS 계약을 따른다. HTML 화면 설계와 최신 디자인 보드도 같은 기준을 사용한다.
- 추가 비교안으로 밝고 청량한 파랑과 편안한 초록 테마를 카탈로그에 둔다. 세 색상안은 각각 라이트·다크를 제공하며 글꼴·배치를 공유한다. 제품의 테마 선택·저장 방식은 아직 결정하지 않았다.
- 색상 비교 이후에는 Material 기본 외형을 그대로 사용하지 않고 MDive의 공통 컴포넌트를 구체화한다. 회사의 공식 사례를 조사하고, 기초 규칙·컴포넌트의 역할·변형·상태·접근성을 실행 카탈로그에서 먼저 검토한다. 사용자에게 캡처를 기본 검토 산출물로 보여주지 않는다. 홈·읽기 화면 적용은 컴포넌트 검토 이후 진행하며, 미정 제품 정책을 시각 초안으로 확정하지 않는다.
- 글꼴 선정은 에이전트에게 위임했다. 첫 카탈로그에는 본문·제목·UI·표 Pretendard, 코드 JetBrains Mono 조합을 사용한다. 선정 근거·배포 조건·시각 검증 항목은 [타이포그래피](typography.md)에 기록하며 최종 시각 승인은 카탈로그 검토 후 진행한다.
- 디자인 시스템은 공통 원본에서 HTML·Compose용 토큰과 양쪽 카탈로그를 생성하는 방향으로 관리한다. 컴포넌트의 실제 표현 코드는 각 환경에서 작성하고, 공통 예시와 상태 목록을 대응시킨다.
- 시각 검증은 Compose 디자인 시스템 카탈로그에서 진행한다. 카탈로그 작업과 제품 화면의 기능 구현은 구분하며, 제품 호스트 구현과 별도로 전체 디자인 검토와 외부 공개 배포는 아직 완료하지 않았다.
- 제품 `app`과 공통 라이브러리 `designsystem`, 그 하위의 독립 카탈로그 앱 `:designsystem:catalog`로 분리한다. 카탈로그를 제품의 debug 런처에서 분리해 각 앱을 따로 실행한다. 공통 JSON 원본과 Python 생성기, HTML·Compose 카탈로그의 역할 및 실행 방법은 [디자인 시스템](design-system.md)에서 관리한다. 기존 HTML의 색상과 수치를 새 디자인의 확정 값으로 사용하지 않는다.
- 공통 상단바는 카탈로그에서 검토하고, 앱 하단 탐색바는 독립적인 최상위 목적지가 없는 현재 흐름에서는 추가하지 않는다. 홈에서 직접 연 문서의 뒤로는 홈 복귀이며, 다른 상단 도구 배치와 상대 문서 이동 후 복귀는 관련 기능 명세에서 구분한다.
- 앱 아이콘은 사선으로 연결된 `md`와 d 안팎의 물결이 있는 시안 10을 사용자 승인했다. [브랜드 원본·Android 리소스·UI 대표 심볼](../../design-system/brand/README.md)을 함께 관리하며, 디자인 시스템의 아이콘 카탈로그와 공통 상단바에서도 재사용한다.

## 열린 결정

- 채택한 문법의 정확한 방언·표기법·호환 버전, GitHub 참조의 저장소 문맥·해석 정책, HTML·미디어 처리 정책, 코드 강조 언어, 합의한 구분자 외 수식 세부 기능과 Mermaid 종류.
- 이미지 폴더의 허용 범위 밖 경로·잘못된 연결·권한 상실 복구, 웹 이미지 오프라인 안내·대체 텍스트와 기타 링크 처리. 기준 폴더·재실행 유지·웹 실패 재시도는 위 합의를 따른다.
- 검색 일치·강조·결과 이동의 상세 규칙, 문서 변경 시 읽던 위치 복원, 책갈피 복원 불가 후 처리.
- 최근 문서 유지 범위·기록 시점, 즐겨찾기 정렬, 파일 재연결 시 동일 문서 판별과 관련 정보 보관.
- 읽기 도구·확대·상대 문서 이동 등 나머지 복귀·취소 동작, 글자 크기 조절 범위, 큰 문서·접근성·태블릿의 기대 경험.

구체적인 질문은 각 기능 명세에서 관리한다. 구현 결과를 바꾸는 미정 사항은 해당 구현 전에 사용자와 결정한다.

## 문서와 구현 기준

화면 명세와 디자인은 분리해 유지한다. 명세의 요소 동작·상태 설명은 보존하고 옆 화면 그림만 최신 디자인 보드의 iframe으로 재사용한다. 샘플·시연은 정책 확정이나 앱 구현 완료를 뜻하지 않는다.

기획은 저장소의 Markdown과 HTML로 관리하며 [제품 기획과 화면 설계서](planning.md)의 역할 분담·검증 방식을 따른다. 구현은 Kotlin·Jetpack Compose·MVI·Hilt, 여러 화면 이동은 Navigation 3를 사용한다. 제품 결정이 구조에 영향을 주면 [아키텍처 문서](../engineering/architecture.md)를 갱신한다.

## 문서가 있는 홈의 파일 열기 · 확정

문서 목록이 있는 홈에서 파일 열기는 문서+더하기 결합 아이콘과 `파일 열기` 라벨의 우하단 FAB로 제공한다. 본문 영역의 오른쪽·아래 16dp에 두고 목록 끝에 FAB 높이와 간격만큼 스크롤 여유를 확보한다. 첫 실행 홈은 기존 중앙 파일 열기를 유지하고 FAB를 중복 표시하지 않는다. 접근 실패·목록 제거 다이얼로그가 열린 경우 배경 FAB도 다른 배경과 함께 비활성/접근성 제외로 처리한다. 로딩·목록 전체 실패에서의 파일 열기 사용 가능 여부는 기존 미정 범위를 유지한다. 이번 범위는 디자인 화면과 DS이며 제품 앱 적용은 후속 요청을 기다린다.
