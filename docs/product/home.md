# 홈과 문서 바로가기

합의 상태: 첫 버전 기능과 홈 화면 기본 구성 승인. 사용자가 S-02 시안을 검토하고 승인했다. 세부 디자인과 미정 정책은 이후 구체화한다.

## 사용자와 목표

Markdown 문서를 자주 읽는 사용자가 새 파일을 열고, 자주 보는 문서와 최근에 읽은 문서에 다시 접근한다.

## 핵심 시나리오

- 처음 앱을 연 사용자는 홈에서 파일 열기를 시작한다.
- 사용자는 홈의 즐겨찾기 또는 최근 문서를 선택해 읽기 화면으로 이동한다.
- 읽기 화면에서 별표로 현재 문서를 즐겨찾기에 추가하거나 해제한다.

## 첫 범위

- 홈에서 파일 하나를 선택하는 진입점을 제공한다.
- 즐겨찾기를 최근 문서보다 위에 표시한다. 최근 문서는 최근에 읽은 순서로 제공한다.
- 처음 실행해 문서가 없는 경우 파일 열기 중심으로 안내한다. 문서가 물에 잠기며 비대칭 물결과 파문이 이어지는 단색 일러스트를 승인했으며, DS·디자인 보드에 반영한다. 짧은 환영 문구·사각 문서 아이콘 제거와 구체 배치는 검토안이며 제품 앱 반영은 별도 결정한다.
- 홈 목록은 문서를 다시 여는 바로가기다. 문서 복사·동기화·편집 기능은 이번 합의에 포함하지 않는다.
- 즐겨찾기는 기기 내에 저장해 앱 재실행 후에도 유지한다.
- 파일 이동·삭제·접근 권한 상실로 열기에 실패하면 항목을 자동 삭제하지 않고 이유를 안내한다. 파일 다시 연결로 접근을 복구하거나 목록에서 제거할 수 있다. 목록에서 제거해도 원본 파일은 삭제하지 않는다.
- 폴더 탐색·Git 연결·편집은 [제품 방향](overview.md)의 확장 후보로 유지한다.

## 첫 파일 선택 흐름의 이동·실패 처리 · 확정

stash에 보관했던 합의를 복원한다. 전체 홈 목록 구현 순서와 첫 버전의 기능 채택은 별개다.

- 파일 선택을 취소하면 홈을 유지한다.
- 홈에서 직접 연 문서는 읽기 상단 뒤로·시스템 뒤로로 홈에 복귀한다. 상대 문서로 이동한 뒤의 복귀는 별도 미정 사항이다.
- 파일 선택 후 열기에 실패하면 읽기 화면에서 재시도·홈 복귀를 제공한다.
- 홈의 기존 바로가기 접근 실패는 홈과 항목을 유지한 채 다이얼로그에서 이유·파일 다시 연결·목록 제거·닫기를 제공한다. 목록 제거는 기존 별도 확인으로 이어진다. 새 파일 열기 실패와 홈 목록 실패를 같은 상태로 합치지 않는다.
- 목록 제거는 확인 다이얼로그에서 취소·제거를 선택하고 원본 비삭제를 안내한다. 관련 즐겨찾기·책갈피 정보의 보관 정책은 여전히 미정이다.

## 화면 상태 표현 · 확정 방향과 검토안

- 목록을 준비하는 전체 로딩은 제목과 문서 행 구조의 스켈레톤으로 표현하며, 첫 실행의 빈 상태와 구분한다. 자리표시자는 문서 데이터나 선택 가능한 항목이 아니다.
- **검토안·승인 대기:** 첫 실행·빈 목록·전체 실패의 아이콘 타일을 없애고, 실패는 원인 안내와 복구 행동을 우선하는 안을 DS·디자인 보드에서 검토한다. 제품 앱 반영은 사용자 결정 뒤 진행한다. 원인별 문구·재시도 정책은 아래 열린 결정으로 유지한다.
- 로딩은 접근성 이름을 한 번 제공하고 스켈레톤 막대는 접근성 트리에서 숨긴다. 불필요한 움직임을 만들지 않으며 모션 제한을 존중한다.

## 합의된 동작의 수용 기준

- 문서 이력이 없는 첫 실행에서도 홈에서 파일 열기를 시작할 수 있다.
- 읽기 화면에서 현재 문서를 즐겨찾기에 추가하면 홈의 즐겨찾기에서 해당 문서를 찾을 수 있다.
- 즐겨찾기를 해제하면 홈의 즐겨찾기 목록에서 제외된다. 원본 파일 삭제로 처리하지 않는다.
- 홈의 문서 바로가기를 선택하면 접근 가능한 해당 문서를 읽기 화면에서 연다.
- 즐겨찾기는 앱을 다시 실행한 후에도 유지한다.
- 문서 접근 실패 시 항목을 자동 삭제하지 않고 파일 다시 연결·목록에서 제거를 제공한다. 목록 제거는 원본 파일을 삭제하지 않는다.
- 최근 문서는 마지막으로 읽은 순서대로 표시한다. 성공적으로 연 시점 등 기록 시점의 상세 정의는 아래 열린 결정에서 정한다.

## 화면 설계서

- [S-02 홈](screens/home.html#s-02): 문서가 있는 상태와 첫 실행 상태, 요소별 동작과 상태 설명.
- [S-01 읽기](screens/reader.html#s-01): 즐겨찾기 추가·해제 진입점. 기존 읽기 기본 방향은 승인됐으며 별표 배치는 검토용이다.

## 열린 결정

- 즐겨찾기 정렬, 목록 표시 정보, 최근 문서 보관 개수와 이력 정리 기능.
- 최근 문서 목록의 앱 재실행 후 유지 범위, 동일 문서 식별, 최근 문서 기록 시점과 중복 처리. 즐겨찾기 재실행 유지는 합의된 범위다.
- 재연결한 파일의 동일 문서 판별, 책갈피 승계와 목록 제거 시 관련 정보 보관 범위.
- 목록 로딩 표시 시점·파일 열기 사용 가능 여부, 실패의 원인별 문구와 재시도 방식, 즐겨찾기 저장 실패 시 상태와 안내. 전체 로딩의 스켈레톤 표현은 확정이다.
- 홈 복귀 시 목록 갱신·스크롤 유지, 상대 문서 이동 등 다른 복귀 상세. 읽던 위치 기억 기능은 [읽기 도구](reading-tools.md)에서 관리한다.

이 항목들은 구현 전에 필요한 범위에서 합의한다. HTML의 예시 파일명·날짜·표시 개수는 제품 정책을 확정하지 않는다.

## 디자인 리뷰 반영안 · 앱 적용 대기

재방문 홈의 큰 환영 영역과 상단 파일 열기를 줄이고 문서 목록을 우선한다. 첫 실행의 승인 일러스트·내용 폭 L 버튼과 빈 상태의 내용 폭 M 단일 복구는 디자인 검토안이다. 기능 삭제나 기존 열린 정책의 확정을 뜻하지 않으며 제품 앱은 이번 변경에 적용하지 않는다.

## 문서가 있는 홈의 파일 열기 위치 · 확정

문서가 있는 홈은 우하단 문서+더하기 아이콘·`파일 열기` 라벨의 FAB를 사용한다. 오른쪽·아래 16dp, 목록 끝 스크롤 여유를 확보해 마지막 문서를 가리지 않게 한다. 첫 실행은 중앙 CTA만 유지해 중복하지 않는다. 접근 실패/목록 제거 확인이 열린 동안 배경 FAB는 비활성·접근성 제외다. 로딩·전체 실패에서의 제공 여부는 미정이며 이번 디자인 보드에는 추가하지 않는다. 제품 앱 반영은 후속 범위다.

문서가 있는 홈의 파일 열기는 문서+플러스 아이콘만 있는 원형 플로팅 버튼으로 제공한다. 접근성 이름은 파일 열기이며 스크롤에 따른 확장·펼침 애니메이션은 사용하지 않는다. 첫 실행은 기존 중앙 버튼을 유지한다.
