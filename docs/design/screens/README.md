# 제품 화면 디자인 초안

[실행 가능한 화면 디자인과 Compose 대응 명세](index.html) · [컴포넌트 사용 기준](component-usage.md) · [41개 화면 색인](screen-index.json)

제품 동작의 원본은 `docs/product/`의 기능 명세와 화면 설계서다. 이 폴더는 최신 DS를 조합한 별도 시각 초안이며 전체 디자인의 최종 승인이나 제품 Android 구현 완료를 뜻하지 않는다. 기존 승인 흐름과 미정 문법·제품 정책을 유지한다.

## 열기와 검토

`index.html`을 로컬 브라우저로 연다. 서버·네트워크·추가 설치가 필요 없다. 공통 자산·글꼴을 상대 경로로 참조하므로 이 폴더만 분리해 이동하지 않는다.

상단에서 세 색상안·라이트/다크·320/360/390 기준 폭·100/130/160% 글자를 비교한다. 목록이나 URL anchor로 보드를 선택하며, **모든 화면 보기 · 인쇄**는 전체 보드를 표시한다. JavaScript 없이도 모든 보드와 인접 명세를 읽을 수 있다. 실제 인쇄 결과와 Android의 인셋·fontScale·IME·TalkBack·모션 검증은 별개다.

화면 버튼은 보드 이동과 시연 피드백이다. 파일 선택·검색·저장·클립보드·네트워크·확대 제스처를 구현하지 않는다. 검색 건수와 슬라이더 범위는 예시이며 제품 정책의 원본이 아니다. 시스템 파일·폴더 선택기는 앱 고유 디자인 범위에서 제외한다.

## DS 재사용

제품 화면과 HTML 카탈로그는 같은 `design-system/components.css`·`feedback.css`·`components.js`를 직접 사용한다. `catalog.css`는 카탈로그 페이지용이므로 제품 화면에서 로드하지 않는다. 값과 아이콘은 공통 JSON 원본, 생성 CSS/Kotlin은 생성기로 관리한다.

버튼·상단바·문서 행·검색·탭·문서 콘텐츠·배너·상태·시트·다이얼로그·입력은 공통 클래스와 구조를 사용한다. `screens.css`는 배치·스크롤·검토 도구와 명시한 화면 전용 영역만 담당한다. [상세 대응표와 허용 영역](component-usage.md)에 기존 Compose API도 연결한다.

- 버튼은 4타입과 S/M/L을 조합한다. 배너 행동은 공통 오른쪽 영역 안에 세로로 쌓고, 좁은 폭·큰 글자에서만 아래 오른쪽으로 이동한다.
- 첫 실행·빈 상태·전체 실패는 본문 가용 영역 중앙, 목차·책갈피 빈 상태는 탭 아래 중앙에 배치한다. 전체 로딩은 중앙 상태 아이콘 대신 화면별 목록/본문 스켈레톤을 표시한다. 넘치는 내용은 위쪽부터 스크롤할 수 있게 한다.
- 시트는 가운데 제목, X·제목 아래 구분선 없음, 핸들 상하 6dp 기준을 공유한다. 본문만 스크롤하며 검토 보드의 핸들 클릭은 닫기 시연이다.
- 체크리스트는 읽기 전용이다. 각주 이동·복귀·접기 초기 상태·HTML 허용 정책은 시각 예시로 확정하지 않는다.
- 문서·코드·표·수식·이미지 셸은 DS를 사용하고, 그림과 수식 내부 내용은 준비된 slot 예시다. 파서·로더·렌더 엔진은 포함하지 않는다.

## 검증 기록 · 2026-10-27

PR #9 병합 커밋 `7dba87a`가 시작 시 `develop` HEAD에 포함됨을 확인했으며, 작업 브랜치는 `docs/refresh-product-screen-designs`다. 커밋·푸시·PR은 하지 않았다.

이전 단계에서는 Compose 카탈로그의 확장 콘텐츠·버튼 크기·48dp 클릭 영역을 API 37 에뮬레이터에서 확인했다. 자동 기기 테스트는 기존 Espresso 3.5.1의 API 37 `InputManager.getInstance` reflection 호환 오류로 콘텐츠 검증 전에 실패했다. 개인 기기는 사용하지 않았다.

이번 공유 렌더러 정리에서는 공통 CSS/JS 직접 참조, 공통 마크업·아이콘 계약, 제품 CSS 외형 덮어쓰기 방지, 40보드 색인·고유 ID·이동 대상과 로컬 자산을 정적으로 검사한다. 생성물 최신 검사·Python 회귀 22개·JS 구문·debug 빌드·앱 단위 테스트·독립 검토가 통과했다. 독립 검토의 disabled primary 색·인쇄 코드/표·렌더 슬롯 폭 회귀는 공통 DS 원본에서 수정했다.

내장 브라우저 정책이 `file://` 열기를 차단했으므로 이번 HTML의 실제 배치·좁은 폭·큰 글자·가로 넘침·인쇄·키보드 렌더는 미검증이다. 기존 34보드 시점의 렌더 기록이나 이전 Compose 실행을 이번 HTML의 검증으로 확대 해석하지 않는다. 이번 정리는 기존 Compose API를 대조했지만 Compose 컴포넌트 코드는 추가 변경하지 않았다.

## 상단바·기본 화면 여백 갱신 · 2026-10-27

홈 8개 보드의 앱명 글자를 제거하고 기존 브랜드 아이콘과 접근성 이름 `MDive`를 유지했다. 읽기 문서 제목·뒤로·도구는 보존한다. 홈·읽기 본문은 공통 page 여백(16dp)을 사방에 사용하고, 도구 행·안내 오버레이의 좌우도 같은 기준으로 맞춘다. 상태 화면 중앙 배치와 DS 컴포넌트 내부 간격·시스템 인셋은 유지한다. 기존 `docs/product/screens/home.html`·`reader.html`에도 브랜드와 본문 여백을 맞췄다.

공유 컴포넌트 계약 정적 테스트 4개와 diff 검사를 통과했다. 로컬 HTML 자산·화면 anchor를 확인했으며, `#all`은 기존 JavaScript 전체 보드 보기 명령이다. 최초 `file://` 열기는 차단됐지만 로컬 HTTP로 내장 브라우저에서 정상 렌더링했다. 홈(문서 있음) 390dp·100%, 홈 첫 실행과 읽기 부분 실패 보드 320dp·160%에서 브랜드 전용 상단바, 안내·제목·도구·줄바꿈을 시각 확인했다. 전체 40보드·다크·인쇄·키보드·기존 독립 와이어프레임의 실제 렌더는 미검증이다.

## 화면별 로딩 방향·첫 실행·실패 표현 검토안 · 2026-10-27

사용자 확정은 화면 전체 로딩의 스켈레톤 방향과 승인 원본의 문서 퐁당 일러스트 자체다. 구체 막대 배치와 첫 실행 전체 구성·빈/실패 표현은 승인 대기 검토안이다. 제품 앱에는 이번 개편을 적용하지 않는다. 현재 보드의 홈 목록 준비와 읽기 전체 로딩은 각각 목록 제목/문서 행 및 본문 제목/문단 줄 스켈레톤으로 조합했다. status 이름을 한 번 제공하고 장식 막대는 숨긴다. 첫 실행 검토안은 승인된 문서 퐁당 일러스트와 짧은 환영 문구·열기, 빈/전체 실패는 아이콘 타일 없이 문구·복구 행동을 표시한다. 부분 리소스 spinner·배너는 유지한다. 정적 접근성 계약 검사·공유 컴포넌트 테스트 4개·diff 검사를 통과했으며, 실제 브라우저 검증 결과는 이번 실행 담당의 별도 기록을 따른다.

첫 실행 검토안의 일러스트를 사용자 승인 ImageGen 단색 PNG에서 자동 트레이스한 `design-system/illustrations/document-plunge.svg`로 교체했다. 임의로 재창작하지 않으며 공통 SVG mask를 primary 색으로 표시해 세 색상안·라이트/다크를 따른다. 일러스트 자체만 확정이고 전체 배치·문구는 검토안이다. 사용자 요청에 따라 직접 브라우저 시각 확인은 생략했으며 제품 앱에는 이번 개편을 반영하지 않았다.

## 두 차례 디자인 리뷰 반영 · 앱 적용 대기

재방문 홈을 문서 우선으로 줄이고 상태별 CTA를 내용 폭으로 조합했다. 읽기는 뒤로·제목·즐겨찾기·검색·더보기 한 행이며 `reader-more`(D-41)는 우상단 앵커 팝업 메뉴다. 목차·책갈피를 첫 항목으로, 위치 책갈피 추가·읽기 설정을 이어 제공하고 즐겨찾기는 독립 상단 토글로 둔다. 기능 삭제나 자동 숨김을 도입하지 않는다. 일반 전체 오류는 재시도·홈 복귀만 제공하고 지속 배너는 본문 공간을 확보한다. 정상 렌더의 중립 표시·제목 앞뒤 리듬·검색/시트 중복 여백은 DS 계약을 재사용한다. 구체 배치는 디자인 검토안으로 제품 앱에는 적용하지 않았다. 사용자 요청에 따라 브라우저·스크린샷 검증은 생략하고 정적 회귀만 수행한다.

정적 회귀 결과: 공유 HTML 컴포넌트 계약 4개 통과. 41개 보드 색인·고유 ID·이동 대상, 읽기 상단 4개 컨트롤, 더보기의 기존 행동 보존, 지속 오류의 viewport 내부 배치, 정상 렌더 중립 상태를 별도 구조 검사로 확인했다. 실제 좁은 폭·큰 글자·줄바꿈·인쇄는 소스 기반 검토에 한정되며 브라우저에서 확인하지 않았다.

최종 계약 조정 후 수치 계약 테스트 3개, Python 회귀 26개, 생성물 검사 2개, JavaScript 구문 검사가 통과했다. 카탈로그 빌드와 제품 앱 컴파일도 통과했으며 독립 검토의 수정 확인을 마쳤다. Compose는 기존 Flow ColumnScope를 유지하고 명시 `MDiveMarkdownSection` 조합으로 제목 32/8·본문 16 리듬을 제공하며, HTML 직접 제목의 자동 CSS와 구분한다. 이번 후속 작업은 제품 앱 코드를 수정하지 않았고 직접 시각 검증도 수행하지 않았다.

홈 기존 문서 접근 실패는 홈을 유지하는 복구 다이얼로그로 변경했다. 파일 다시 연결·목록 제거의 별도 확인·닫기를 제공한다. 첫 실행 일러스트와 환영 제목 사이는 기존보다12px 늘렸다. HTML 계약4개와 diff검사 통과, 직접시각확인은 생략했다.

## 문서 목록 홈의 파일 열기 FAB · 2026-10-27

문서가 있는 홈 5개 보드의 상단 파일 열기를 제거하고 문서+더하기 아이콘·파일 열기 라벨의 우하단 FAB로 옮겼다. 기본 inset은 16dp이며 목록 끝에 버튼 높이와 간격을 예약한다. 첫 실행은 중앙 CTA만 유지하며 접근 실패/목록 제거 다이얼로그의 배경 FAB는 비활성·접근성 제외다. 기존 접근 실패 다이얼로그와 첫 실행 일러스트 아래 12dp 추가 여백은 보존했다. 로딩/전체 실패의 사용 가능 정책과 제품 앱은 변경하지 않았다. 사용자 요청에 따라 브라우저·스크린샷 검증은 하지 않는다.

검증 결과: Python 회귀 26개와 diff 검사 통과. FAB 5개 상태·첫 실행 중복 없음·모달 배경 제외·legacy 기기 프레임 내부 배치·일러스트 추가 여백 보존을 정적으로 확인했다.

## 상단 즐겨찾기·앵커 팝업·오류 맥락 정리

Acrobat의 공통 상단 작업/overflow 분리와 Android의 호출 버튼 앵커 popup 원칙을 참고해 `reader-more`를 하단시트에서 우상단 팝업으로 바꿨다. 즐겨찾기는 상단 독립 토글로 옮기고 메뉴의 중복 항목을 제거했다. 일반 읽기 열기 실패는 재시도·홈 복귀만, 홈 기존 문서 접근 실패는 파일 다시 연결·목록 제거·닫기로 구분한다. 출처와 적용 범위는 [DS 가이드](../../product/design-system.md#읽기-상단-팝업-메뉴와-오류-복구-구분)에 기록했다. 제품 앱과 미정 재연결 규칙은 변경하지 않았으며 직접 시각 검증은 수행하지 않는다.

검증 결과: Python 회귀 26개·JavaScript 구문·diff 검사 통과. 28개 읽기 상단의 4개 컨트롤/독립 즐겨찾기, 팝업 메뉴의 도구 3개와 닫기, 일반 오류와 기존 문서 재연결의 행동 구분을 정적으로 확인했다. 메뉴 시연은 항목 이동·바깥 클릭·Escape 닫기·화살표 키 포커스 이동과 즐겨찾기 aria-pressed 전환을 제공하지만 직접 브라우저 조작은 검증하지 않았다.

## 명세의 화면 그림 재사용

화면 명세는 별도로 유지하며 최신 디자인 보드를 `index.html?embed=<board-id>#<board-id>`로 불러온다. embed 모드는 검토 탐색·보드 제목·인접 디자인 설명을 숨기고 원본 제품 프레임만 표시한다. 명세는 자체 요소별 동작·상태·합의/미정 설명과 원본 열기 링크를 유지한다. 디자인 문서가 제품 명세를 대체하거나 샘플 정책을 확정하지 않는다. 이번 변경은 직접 시각 검증 없이 정적으로 검사한다.

명세 재사용 정적 검증: 홈 6개·읽기 8개 iframe의 대상 보드·접근성 title·원본 링크와 명세의 기존 anchor/설명/미정 표시를 확인했다. 명세에서 복제된 제품 SVG·폰 마크업을 제거했고 공통 보드만 불러온다. Python 회귀 26개·JavaScript 구문·diff 검사를 통과했다. 직접 브라우저 렌더·인쇄는 미검증이다.
